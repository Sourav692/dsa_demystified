90 · Subsets II

Every distinct selection when some numbers repeat.

The problem, in plain words

Same task as Subsets: list every possible selection. The catch: some numbers repeat. Two selections that hold the same numbers are the same answer, so each may appear only once.

Example: [1, 2, 2] → [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]. Six answers, not eight: [2] made from the first 2 or the second 2 is one answer.

The trick is to never build a repeat, instead of building all 8 and throwing two away.

Solution 1 — Brute force: build all, throw repeats away

Sort the numbers, then build every one of the 2ⁿ position subsets with a bitmask, exactly like Subsets. Turn each into a tuple and keep it only if the "seen" set does not have it yet.

seen / out (kept)

Speed & memory: always builds all 2ⁿ subsets, even when most are repeats — Θ(n·2ⁿ) time on every input; the set holds every distinct subset — O(n·D) memory (D = number of distinct subsets).

Solution 2 — Include / exclude, skip the whole run when excluding (the pattern)

Sort, so equal numbers sit together. Include works as in Subsets: take this copy and move one step right (the next copy may be taken too). Exclude jumps past every copy of this value at once: if you decline one 2, declining or taking a later 2 would only rebuild lists you already have. So each value is taken 2 times, 1 time, or 0 times — each count exactly once.

Solution 3 — Start-index loop, skip a repeated sibling

Same as Subsets' start-index loop: save every partial selection on arrival, then try each number to the right as the next pick. New rule: within one loop, a value may be the "next pick" only once. If nums[i] equals the number just before it in this same loop (i > start), skip it. The first pick of a loop is always allowed, which is how [2, 2] still gets made.
