78 · Subsets

List every possible selection of a set of distinct numbers.

The problem, in plain words

You have a few different items. List every possible selection of them: taking none, taking one, taking two, and so on up to taking all of them. Order inside a selection does not matter, and no selection may appear twice.

Example: [1, 2, 3] → [[], [1], [2], [3], [1, 2], [1, 3], [2, 3], [1, 2, 3]]. Think "which toppings could go on a pizza": each topping is on or off.

Every extra item doubles the count: 3 items give 8 subsets, 10 items give 1024.

Solution 1 — Brute force: count in binary

Write the numbers 0 to 7 in binary: 000, 001, …, 111. Each pattern of three on/off bits is one subset: bit i on means "take nums[i]". Eight numbers, eight subsets, none repeated.

out

Speed & memory: 2ⁿ masks, each checking n bits — O(n·2ⁿ) time, O(n) extra memory besides the answer. No method can be faster: the answer itself has 2ⁿ lists.

Solution 2 — Backtracking: include or exclude each number (the pattern)

Walk the numbers left to right. At each one, make a yes/no choice. First say yes: add it to path, decide the rest, then take it back out (pop). Then say no: decide the rest without it. When every number is decided, path is one subset: save a copy.

Solution 3 — Backtracking: pick the next number from the right (start index)

Every partial selection is already a subset, so save it the moment you arrive. Then try each number to the right of the last one picked as the next pick. Only moving right means [1, 2] gets built but [2, 1] never does.

When you'd use this

See "all subsets", "power set", "every combination of any size", or "each item is either picked or not"? Use the include/exclude backtracking template. If the input can repeat values, sort and skip: Subsets II.
