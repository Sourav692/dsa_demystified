Subsets

Generate every subset by making one yes/no decision per element. Include it, explore, take it back out; then exclude it and explore again. The recursion tree has exactly one leaf per subset. With repeated values, sort first and skip equal values at the same decision point so no subset is built twice.

Core idea: include / exclude, then un-choose Method 1: Subsets Method 2: Subsets II, run skip Method 3: start-index sibling skip Interactive traces synced to code

Canonical example

Answer = 8 subsets: [[1, 2, 3], [1, 2], [1, 3], [1], [2, 3], [2], [3], []]

Why this pattern matters

Try every on/off combination

Feature flags to test together, items to pack, people to put on a team: when each thing is either in or out, the candidates are exactly the subsets.

The backtracking template in its smallest form

Choose, explore, un-choose. Subsets has no target, no pruning and no ordering, so the bare mechanics are all you see.

One template, a whole family

Combinations (subsets of size k), Combination Sum and Combination Sum II change only the base case or add one skip line.

Instructor note: the output has 2ⁿ lists, so every correct solution is O(n·2ⁿ). The interview is not about beating that; it is about writing the recursion cleanly, recording copies, and not producing duplicates.

What is the Subsets pattern?

Simple definition

A recursive function backtrack(i) decides element i. It keeps one shared list, path, holding the elements chosen so far. It tries the branch with nums[i] (append, recurse, pop) and the branch without it (recurse). When i reaches n, every element is decided and path is one finished subset.

The tell in a problem statement

"All subsets", "power set", "every combination of any size", "each element is either picked or not". With "may contain duplicates" plus "must not contain duplicate subsets", add sort + skip.

Beginner shortcut: n yes/no decisions give 2ⁿ leaves. If your recursion records anything at a node that is not a complete decision, or records path instead of path[:], the count or the contents will be wrong.

Step-by-step thinking process

1

Spot "every selection"

The answer lists all subsets, so the work must enumerate them: backtracking.

2

One decision per index

backtrack(i) decides nums[i]: include it or exclude it.

3

Choose, explore, un-choose

path.append, recurse, path.pop(), then recurse again for the exclude branch.

4

Record a copy; handle repeats

At i == n append path[:]. If values repeat, sort and let the exclude branch skip the whole run.

How the input becomes a decision tree

The input is a flat list. The algorithm never builds a tree object: the tree is the shape of the recursive calls. Each level of calls decides one index, and each call has two children, one for "include" and one for "exclude".

Input list

nums = [1, 2, 3]
→

Calls per level

backtrack(0): 1 call decides 1 backtrack(1): 2 calls decides 2 backtrack(2): 4 calls decides 3 backtrack(3): 8 leaves = 8 subsets

Index 0: decide 1

Two branches: paths starting [1] and paths starting [].

Index 1: decide 2

Each branch splits again: [1, 2], [1], [2], [].

Index 2: decide 3

Eight paths, one for every in/out pattern of three elements.

Index 3: leaves

Nothing left to decide: each leaf records path[:]. That is the whole answer.

Critical point: there is only one path list. Every branch appends to it and pops from it. That is why the pop must mirror the append exactly, and why a leaf must store a copy: by the end, path is empty again.

Method 1: include / exclude (Subsets)

The template itself, line for line from the notebook's subsets_include_exclude, traced on nums = [1, 2, 3]. Watch path grow on include, shrink on pop, and out grow only at the leaves.

def subsets_include_exclude(nums: List[int]) -> List[List[int]]: out, path = [], [] def backtrack(i: int) -> None: if i == len(nums): # base case: every element decided out.append(path[:]) # record a COPY; `path` keeps changing return path.append(nums[i]) # INCLUDE nums[i] backtrack(i + 1) path.pop() # UN-CHOOSE: undo before the other branch backtrack(i + 1) # EXCLUDE nums[i] backtrack(0) return out

Key mental model

Each element is a light switch. The recursion flips switch i on, explores every setting of the later switches, flips it off, and explores them again. Eight leaves, eight switch settings.

Common mistake

Forgetting path.pop(). At step 5 the exclude branch for 3 would start with [1, 2, 3] still in path, so "excluded" subsets would contain 3.

Why one shared list

Appending and popping at the end of a Python list is O(1). Copying only at the 2ⁿ leaves keeps the total at O(n·2ⁿ), the size of the output.

Method 2: skip the whole run on exclude (Subsets II)

Now nums = [1, 2, 2]. Plain Method 1 would build [1, 2] and [2] twice, once per copy of 2. Sort first so the copies are adjacent. Include is unchanged. Exclude moves j past every copy of nums[i]: declining one 2 means declining all remaining 2s. Code from the notebook's subsets_with_dup_include_exclude.

def subsets_with_dup_include_exclude(nums: List[int]) -> List[List[int]]: nums = sorted(nums) # duplicates become one adjacent run n = len(nums) out, path = [], [] def backtrack(i: int) -> None: if i == n: out.append(path[:]) # every value decided: record a copy return path.append(nums[i]) # INCLUDE nums[i] (the next copy may follow) backtrack(i + 1) path.pop() # UN-CHOOSE j = i + 1 while j < n and nums[j] == nums[i]: # EXCLUDE nums[i] -- and every remaining j += 1 # copy of it, in one jump backtrack(j) backtrack(0) return out

Key mental model

For a value with c copies, the real choice is how many to take: c, c − 1, …, 0. Include steps through the copies one by one; the jump ends the run. Steps 7 and 15 show the jump 1 → 3.

Common mistake

Skipping the run on the include branch instead. Then a value can only be taken once and [2, 2] and [1, 2, 2] disappear.

Why sorting matters

The skip compares neighbours. Unsorted [2, 1, 2] has its 2s apart, so the while loop would never see the second copy.

Method 3: start-index loop with a sibling skip (Subsets II, alternate shape)

The other common shape. backtrack(start) records path on entry (every node is a subset), then loops over the next element to add. The duplicate rule lives in the loop: if i > start and nums[i] == nums[i - 1]: continue. Within one loop, a value may start a branch only once. Code from the notebook's subsets_with_dup_start_index, same input.

def subsets_with_dup_start_index(nums: List[int]) -> List[List[int]]: nums = sorted(nums) # duplicates become adjacent out, path = [], [] def backtrack(start: int) -> None: out.append(path[:]) # every node is a distinct subset for i in range(start, len(nums)): if i > start and nums[i] == nums[i - 1]: continue # SKIP: the sibling before us built this branch path.append(nums[i]) # CHOOSE backtrack(i + 1) # EXPLORE path.pop() # UN-CHOOSE backtrack(0) return out

Key mental model

The loop asks "which element comes next?". Two equal values at the same position would start identical subtrees, so only the first one may. Steps 6 and 12 are the skips.

Common mistake

Writing i > 0 instead of i > start. At step 3, i = 2 is the first pick of its loop (start = 2); i > 0 would wrongly skip it and lose [1, 2, 2].

Same answer, different order

Both Subsets II methods produce the same 6 subsets: this one in the order [], [1], [1, 2], [1, 2, 2], [2], [2, 2].

Edge cases you should test

Case A: one element

nums = [0]

[[0], []]

One decision, two leaves. The empty subset is always part of the answer; with nums = [] the answer is [[]], not [].

Case B: every value equal (Subsets II)

nums = [3, 3, 3]

[[3, 3, 3], [3, 3], [3], []]

Only n + 1 distinct subsets. The skip makes the backtracking do O(n²) work here, while a build-all-then-dedupe brute force still builds 2ⁿ.

Case C: duplicates not adjacent

nums = [2, 1, 2]

Same 6 subsets as [1, 2, 2]

Both Subsets II methods call sorted(nums) first. Without it the neighbour check misses the second 2.

Case D: Subsets II on distinct values

nums = [1, 2, 3]

All 8 subsets

No run is longer than one, so the skip never fires and the code behaves exactly like Method 1.

How to derive this in an interview

Reasoning path

Every element is either in a subset or not: n binary decisions, 2ⁿ answers.

Recursion over the index makes one decision per level; two recursive calls per level cover both choices.

One shared path: append before the include call, pop after it, record a copy at i == n.

Duplicates? Sort, then make "exclude" skip every copy of the value (or skip equal siblings in a start-index loop).

What to say out loud

  • "Each element is either in or out, so there are 2ⁿ subsets and I'll backtrack over the index with an include and an exclude branch."
  • "I keep one path list, pop after the include branch, and append a copy at the leaves."
  • "It's O(n·2ⁿ) time, which matches the output size, and O(n) extra space for the recursion."
  • "With duplicates I sort, and the exclude branch jumps past the whole run of equal values, so each distinct subset is built exactly once."

Common beginner coding mistakes

Subsets

  • out.append(path) without a copy: every entry is the same list, empty at the end.
  • Missing path.pop() after the include call: the exclude branch still holds the element.
  • Recording at every call in the include/exclude form: internal nodes are not finished decisions, so subsets get recorded more than once.
  • In the start-index form, recursing with start + 1 instead of i + 1: subsets like [2, 1] or repeats appear.

Subsets II

  • Not sorting first: the neighbour checks only catch adjacent copies.
  • i > 0 instead of i > start: [2, 2] is never built.
  • Skipping the run on include instead of exclude: values can never repeat inside a subset.
  • Deduplicating with a set afterwards: correct, but it still pays for all 2ⁿ subsets.

Practice questions

Try each in your head first. Open the hint, then the answer, only after you commit to a guess. Questions 3 and 4 are follow-up variants of this pattern's two problems, not separate problems in the folder.

Practice 1 — Subsets: how many lists for nums = [5, -3], and in what order does include/exclude record them?

Hint: include always runs before exclude, and records happen only at leaves.

Answer: 2² = 4, recorded as [5, -3], [5], [-3], []. Step through the same mechanics on the Subsets page.

Practice 2 — Subsets II: how many distinct subsets does nums = [4, 4, 4, 1, 4] have?

Hint: after sorting it is [1, 4, 4, 4, 4]. Count the choices per distinct value.

Answer: (1 + 1) × (4 + 1) = 10: take 1 or not, and take 0 to 4 fours. The notebook's test prints all 10. Compare all three approaches on the Subsets II page.

Practice 3 (variant) — Combinations, LC 77: only subsets of exactly size k. What changes in Method 1?

Hint: look at the base case, and at when a branch can never reach size k.

Answer: record when len(path) == k (then return), and stop when the index runs off the end. The include/exclude shape stays the same. Its sibling pattern: Combinations.

Practice 4 (variant) — In Method 3 on [2, 2], which calls run and why is [2, 2] still produced?

Hint: the skip needs i > start. What is start when the second 2 is considered after picking the first one?

Answer: backtrack(0) records [], picks nums[0]; backtrack(1) records [2] and picks nums[1] because i = 1 = start; backtrack(2) records [2, 2]. Back in backtrack(0), i = 1 > 0 and equal to its sibling, so it is skipped. Result [[], [2], [2, 2]]. See Method 3 above or the Subsets II page.

Final takeaway

Include, recurse, pop; exclude, recurse; record a copy at the leaf. That is the whole Subsets pattern, and its cost O(n·2ⁿ) is the size of the answer. For repeated values, sort and make each value's copy count a single decision: skip the whole run when excluding, or skip equal siblings in a start-index loop.
