Grid Backtracking

Search a grid for one path of neighbouring cells. Run a DFS from every cell; at each cell check the letter, mark the cell as used, explore its 4 neighbours, then restore it on the way back so a different path can still use it.

Core idea: mark, explore, restore Method 1: backtracking DFS (Word Search) Method 2: the brute force it replaces Interactive traces synced to code

Problem in this pattern: Word Search · pattern notes (README)

Canonical example

Word Search, board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCCED"

Answer = True (path 1 to 6 spells ABCCED)

Why this pattern matters

Word puzzles and board games

Word searches with bends, Boggle-style boards: the answer is a chain of touching squares, and a square can't be used twice in one word.

Paths that must not revisit a square

A robot or a maze walker exploring routes: a square on the current route is off limits, but the same square is fine for a different route.

Backtracking, made visible

It is the same choose, explore, un-choose loop as subsets and permutations. On a grid you can watch the "choose" (a cell turns into #) and the "un-choose" (the letter comes back).

Instructor note: the whole pattern is one decision: the "used" mark belongs to the current path, not to the whole search. Get that right and the code writes itself.

What is grid backtracking?

Simple definition

A depth-first search over grid cells that builds one path at a time. Each step checks the cell, marks it as part of the path, tries the 4 neighbours, and unmarks it when it backs out. "Backtracking" is that backing out: undo the last choice, try the next one.

The tell in a problem statement

A 2D board, an answer that is a path of adjacent cells (up, down, left, right), and a rule like "the same cell may not be used more than once". Small limits (Word Search: board up to 6×6, word up to 15 letters) hint that an exponential search with pruning is expected.

Beginner shortcut: overwrite the cell with # before exploring and write the letter back after. # never equals a letter, so the ordinary "does the letter match?" check also blocks reuse. No visited set needed.

Step-by-step thinking process

1

Try every start

The path can begin anywhere: call dfs(r, c, 0) for every cell and stop at the first True.

2

Prune at once

Off the board, wrong letter, or a #: return False before doing any work.

3

Mark and explore

Save the letter, write #, and ask the 4 neighbours for word[i + 1].

4

Restore and report

Put the letter back, whatever the result, and return what the neighbours found.

How the board becomes a tree of calls

There is no separate data structure to build. The board itself is the graph: each cell is a node, and its up, down, left and right neighbours are its edges. The recursion turns that graph into a tree of calls: dfs(r, c, i) has up to 4 children, one per neighbour, each looking for the next letter.

Input

board = A B C E S F C S A D E E word = "ABCCED"
→

Calls from the first start cell

dfs(0,0,0) A mark dfs(1,0,1) S != B pruned dfs(-1,0,1) off pruned dfs(0,1,1) B mark dfs(1,1,2) F != C pruned dfs(-1,1,2) off pruned dfs(0,2,2) C mark ... deeper ...

Depth = letter index

A call at depth i is looking for word[i]. The tree is at most L = len(word) levels deep.

Children = neighbours

Down, up, right, left, in the code's order. The or chain stops at the first child that returns True.

The current path = the # cells

The cells marked # at any moment are exactly the calls still on the recursion stack.

Returning = un-marking

When a call returns, its cell gets its letter back, so the board always shows the current path and nothing else.

Critical point: after the first step, one of the 4 neighbours is the cell you came from, and it is marked #. So each call has at most 3 useful children, which is where the 3^L in the running time comes from.

Method 1: backtracking DFS (Word Search)

The template itself, line for line from the notebook's exist. Traced on the canonical example: every call in the order the code makes it, including the pruned ones and the restores on the way back.

def exist(board, word): rows, cols = len(board), len(board[0]) def dfs(r, c, i): # can we match word[i:] starting at cell (r, c)? if i == len(word): return True # matched every letter if r < 0 or c < 0 or r >= rows or c >= cols or board[r][c] != word[i]: return False # off the board, or the letter doesn't match tmp = board[r][c]; board[r][c] = "#" # mark this cell used (can't reuse within a word) found = (dfs(r+1,c,i+1) or dfs(r-1,c,i+1) or dfs(r,c+1,i+1) or dfs(r,c-1,i+1)) # try all 4 neighbors for the next letter board[r][c] = tmp # restore the cell (backtrack) return found return any(dfs(r, c, 0) for r in range(rows) for c in range(cols)) # try every start cell

Key mental model

The # cells are the recursion stack drawn on the board. At step 11 the call from E at (2,2) looks up at (1,2), finds #, and is turned away: that C is already on the path.

Common mistake

Returning before the restore line, for example if dfs(...): return True right after marking. On success the caller gets back a board still full of # marks. The notebook's correctness check asserts the board comes back unchanged.

Why mark in the board

Writing # into the cell costs O(1) and needs no extra memory. The letter check on line 6 rejects it for free, so "used" and "wrong letter" are one test.

Method 2: the brute force it replaces (enumerate every path)

The notebook's exist_brute builds every path of exactly L cells that never repeats a cell, and compares letters only when a path is complete. Letters never steer it. Traced on a 2×2 board, [["A","B"],["C","D"]] with word = "BDC": it grows two full paths from A, though the word starts with B.

def exist_brute(board: List[List[str]], word: str) -> bool: rows, cols, L = len(board), len(board[0]), len(word) def paths_from(r, c, path): # yield every self-avoiding path that extends `path` to L cells if len(path) == L: yield path return for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)): nr, nc = r + dr, c + dc if 0 <= nr < rows and 0 <= nc < cols and (nr, nc) not in path: # on the board, not reused yield from paths_from(nr, nc, path + [(nr, nc)]) # letters are ignored here for r in range(rows): for c in range(cols): for path in paths_from(r, c, [(r, c)]): if "".join(board[i][j] for i, j in path) == word: # compare only at the end return True return False

Key mental model

Brute force asks "is this whole path the word?" once per path. Backtracking asks "is this cell the next letter?" once per step, and stops a path at its first wrong letter.

Common mistake

Thinking the worst case got better. On a board of all 'A' with word "A...AB" every letter matches until the last one, so both methods explore the same paths. The notebook measures both growing about 2.1 to 2.5 times per extra letter there.

Where pruning pays

On a board of random letters, the notebook's brute force still grows about 2.1 to 2.5 times per extra letter, while backtracking stays flat (about 1x): almost every path dies at its first letter.

Edge cases you should test

Case A: one cell, one letter

board = [["A"]], word = "A"

Answer = True

dfs(0, 0, 0) matches and marks the A; its first neighbour call has i = 1 = len(word) and returns True before the bounds check, even though that neighbour is off the board.

Case B: reuse would be the only way

board = [["a","a"]], word = "aaa"

Answer = False

Two cells can't spell three letters without stepping on one twice. Without the # mark, the search bounces a, a, a between the two cells and wrongly returns True.

Case C: the word wants a cell already on the path

Canonical board, word = "ABCB"

Answer = False

A, B, C walk along the top row; the only B next to that C is the one at (0,1), already #. No other route exists.

Case D: a cell must be reusable after a failed path

board = [["C","A","A"],["A","A","A"],["B","C","D"]], word = "AAB"

Answer = True

The path (1,1) to (1,0) to (2,0) works, but earlier start cells already walked through (1,1) and failed. Restoring makes (1,1) available again; a never-cleared global visited set returns False here.

Method comparison

MethodTimeExtra spaceTakeaway
Brute force: every path, compare at the end (Method 2)O(rows·cols·3^L·L)O(L)Same work on every board; the letters never cut a path short.
Backtracking DFS: prune, mark, restore (Method 1)O(rows·cols·3^L) worst caseO(L) recursionSame worst case, but a wrong letter ends a path at once; flat on a random board in the notebook.

L = word length. Both grew about 4x per doubling of the grid side in the notebook (time is linear in the number of cells). The complexities and every measured ratio come from the Word Search notebook.

How to derive this in an interview

Reasoning path

The word is a path of adjacent cells, and it can start anywhere: try every cell as a start.

From a cell, the next letter must be in one of 4 neighbours: recursion, one level per letter.

A path may not reuse a cell, but other paths may: the "used" mark must be undone when backing out.

Prune as early as possible: check bounds and the letter before marking anything.

What to say out loud

  • "I'll run a DFS from every cell; dfs(r, c, i) means word[i:] starts at (r, c)."
  • "If the cell is off the board or doesn't hold word[i], I return False right away."
  • "Otherwise I mark it with '#', try the 4 neighbours for the next letter, and restore it on the way back, so other paths can use it."
  • "Worst case O(rows·cols·3^L) time, since after the first step there are at most 3 new neighbours, and O(L) space for the recursion."

Common beginner coding mistakes

Backtracking DFS

  • Forgetting board[r][c] = tmp, or returning before it runs: later searches see a board full of #.
  • One global visited set that is never cleared: flood-fill behaviour, wrong answers (Case D).
  • Marking before the bounds and letter check, then indexing off the board.
  • Stopping after the first start cell that matches word[0]: for "SEE" the S at (1,0) fails and the S at (1,3) succeeds.

Brute force

  • Not excluding cells already in the path, so "paths" revisit cells and Case B wrongly returns True.
  • Sharing one path list between branches without copying or popping it.
  • Comparing letters only at the end and calling it "pruned": nothing is cut until the path is full.
  • Assuming it is slower in big-O on every input: in the worst case both share the 3^L term.

Practice 1 — Word Search: canonical board, word = "SEE"

Hint: the S at (1,0) fails first. Which other S is there?

Answer: True. Path (1,3) S, then down to (2,3) E, then left to (2,2) E. Step through both approaches on the Word Search page.

Practice 2 — Variant: why does one global visited set fail on [["C","A","A"],["A","A","A"],["B","C","D"]], "AAB"?

Hint: which cells do the start cells (0,1) and (0,2) walk through before any path succeeds?

Answer: their failed paths add (1,1) and other A cells to the set and never remove them. The only valid path starts at (1,1), which is now "visited", so the search returns False; the correct answer is True. Mark-and-restore frees the cell when each failed path backs out. Compare with the restore steps on the Word Search page.

Practice 3 — Variant: count every path that spells "AAA" on [["A","A"],["A","A"]]

Hint: replace or with +. Careful with the base case: if i == len(word): return 1 runs once per neighbour call, so it counts each finished path up to 4 times. Return 1 when the last letter matches instead.

Answer: 8 (4 start cells, 2 neighbours each, then 1 unused neighbour). The naive base case reports 32. Same template, see Word Search.

Practice 4 — Variant: Word Search II, many words on one board

Hint: running Method 1 once per word repeats the same board walks. What could prune by prefix for all words at once?

Answer: put the words in a trie (NeetCode's Tries section). Run the same DFS with mark and restore from every cell, walking down the trie as you go; stop when no word continues with this letter, and record a word when you reach its end. The grid part is still this pattern. Base page: Word Search.

Final takeaway

Check, mark, explore, restore. Prune off-board and wrong-letter cells at once, overwrite the cell with # while its neighbours are searched, and put the letter back on the way out. The mark belongs to the current path, which is exactly what separates grid backtracking from flood fill.
