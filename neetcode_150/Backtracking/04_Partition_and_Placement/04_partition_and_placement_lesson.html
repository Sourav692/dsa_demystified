Partition and Placement

Backtracking where each step decides where the next piece goes: where the next substring ends, or which column the next queen takes. Check one cheap rule before committing, recurse to the next position, then undo exactly what you did.

Core idea: prune a piece before recursing on it Method 1: Palindrome Partitioning Method 2: N-Queens with three sets Interactive traces synced to code

Problems in this pattern: Palindrome Partitioning · N-Queens · pattern notes (README)

Canonical example

Palindrome Partitioning, s = "aab". Each circle is a call; the number is start, the edge label is the piece cut.

Answer = [["a","a","b"], ["aa","b"]]

Why this pattern matters

Splitting text into valid tokens

Segmenting a string into dictionary words, IP address parts, or palindromes: every split point is a decision, and every token has a local validity test.

Placing items under constraints

Scheduling, seating, Sudoku, puzzle boards: one slot at a time, each new item checked against the ones already placed.

One loop for both

Palindrome Partitioning and N-Queens share the same choose, check, recurse, undo loop. Only the move, the check, and the state change.

Instructor note: the speed of these solutions comes almost entirely from where the check sits. Check before recursing and dead branches never grow; check at the end and you are back to the brute force.

What is partition and placement backtracking?

Simple definition

The recursion carries a position: the index where the next piece of the string starts, or the row that needs the next queen. From that position it tries every possible next move, skips the moves that break the rule, and recurses on the rest. When the position reaches the end, everything is placed and the arrangement is recorded.

The tell in a problem statement

"Return all ways to partition / split a string so that every piece ...", or "place n items so that no two conflict, return every arrangement". The answer is a list of full arrangements, and a single new piece can be tested on its own.

Beginner shortcut: ask "what is the next position, and what are the moves from it?" For a string: position start, moves s[start:end]. For a board: position row r, moves column c. The rest is the same loop.

Step-by-step thinking process

1

Name the position

start for a string, row r for a board. The goal is reached when it equals the length.

2

List the moves

Every end index start+1 .. len(s), or every column 0 .. n-1.

3

Check before you choose

Skip a piece that is not a palindrome, or a square whose column or diagonal is taken. Make the check O(1) if you can.

4

Choose, recurse, undo

Apply the move, call the next position, then reverse every change the move made.

How the input becomes a decision tree

The input is just a string (or just n). The structure the algorithm walks is never built in memory: it is the tree of recursive calls. Each call is a node, each move is an edge, and the shared path holds the edges from the root to the current node.

Input

s = "aab" # 3 letters n = 4 # 4 x 4 board
→

Implicit tree

node = backtrack(start) / backtrack(r) edge = piece s[start:end] / column c leaf = start == len(s) / r == n dead = check fails: no recursion

Root: backtrack(0)

Nothing placed yet. path = [], or all three sets empty.

Edge: a move that passes the check

"a" is a palindrome, so path becomes ["a"] and the child call starts at index 1.

Dead edge: a move that fails

"ab" is not a palindrome. The child call is never made, so nothing below it is explored.

Leaf: the position reaches the end

start == 3: the pieces in path cover the string. Record a copy, return, and undo the last piece.

Critical point: there is only one path list (one board, one set of sets) shared by every call. That is why each choose must be undone on return, and why an answer must be recorded as a copy.

Method 1: choose the next palindromic piece (Palindrome Partitioning)

The template on a string, taken line for line from the notebook's partition_backtrack. The position is start; the moves are the pieces s[start:end]; the check is "is the piece a palindrome?". Traced on s = "aab".

def partition_backtrack(s: str) -> List[List[str]]: out, path = [], [] def backtrack(start): if start == len(s): # every character is in some piece out.append(path[:]) # record a COPY: path keeps changing return for end in range(start + 1, len(s) + 1): # where does the next piece end? piece = s[start:end] if piece != piece[::-1]: # PRUNE: not a palindrome continue path.append(piece) # CHOOSE backtrack(end) # EXPLORE: the next piece starts at end path.pop() # UN-CHOOSE backtrack(0) return out

Key mental model

path is a stack of pieces that mirrors the recursion: every append is a step down the tree, every pop a step back up. At step 7 the stack is ["a"] again, so trying "ab" starts from a clean state.

Common mistake

out.append(path) without the copy. At step 15 path is [], so both recorded answers would print as empty lists.

Why prune first

"ab" and "aab" are rejected without a recursive call. On a palindrome-poor string like "abcabc…" the notebook measures backtracking near 1x per extra letter, while the enumerate-then-filter brute force grows 2x.

Method 2: place one queen per row with three sets (N-Queens)

The same loop on a board, from the notebook's solve_n_queens_sets. The position is the row r; the moves are the columns c; the check is three set lookups. A \ diagonal keeps r - c constant and a / diagonal keeps r + c constant, so diag and anti store those numbers. Traced on n = 4; blocked squares tried in a row are shown with the next placement or removal.

def solve_n_queens_sets(n: int) -> List[List[str]]: out, cols, diag, anti = [], set(), set(), set() # blocked columns, r-c ids, r+c ids board = [["."] * n for _ in range(n)] def backtrack(r): if r == n: # a queen in every row out.append(["".join(row) for row in board]) # record a COPY of the board return for c in range(n): # which column in row r? if c in cols or (r - c) in diag or (r + c) in anti: continue # PRUNE: attacked by a queen above cols.add(c); diag.add(r - c); anti.add(r + c); board[r][c] = "Q" # CHOOSE backtrack(r + 1) # EXPLORE cols.remove(c); diag.remove(r - c); anti.remove(r + c); board[r][c] = "." # UN-CHOOSE backtrack(0) return out

Key mental model

One queen per row turns "choose 4 of 16 squares" into "choose a column, row by row". The three sets are a summary of every queen above: one lookup each replaces a scan over the placed queens.

Common mistake

Undoing only some of the four changes. If anti.remove(r + c) is missing, a queen that is gone still blocks a / diagonal and solutions disappear.

Why sets

The notebook's scan version checks each square against every queen above, O(n) per check. With sets the check is O(1); at n = 9 the set version measured about 5 ms against about 14 ms for the scan and 130 ms for the permutation brute force.

Edge cases you should test

Case A: one character, one queen

s = "a" and n = 1

[["a"]] · [["Q"]]

One move, then the position equals the length and the single arrangement is recorded. The brute force's range(1 << (n - 1)) is range(1): one empty cut pattern.

Case B: every piece is a palindrome

s = "aaa"

4 partitions = 2^(3-1)

[["a","a","a"], ["a","aa"], ["aa","a"], ["aaa"]]. Nothing is pruned, so this is the worst case: the output itself is exponential, and the notebook measures about 2x per extra letter for every approach.

Case C: only single letters are palindromes

s = "ab"

[["a","b"]]

Every longer piece is pruned at once. This is where backtracking beats the brute force most: one answer, almost no work.

Case D: n = 2 and n = 3

n = 2, n = 3

[] · []

The search runs, every branch dies, and out stays empty. The counts for n = 1..8 are 1, 0, 0, 2, 10, 4, 40, 92, asserted in the notebook.

How to derive this in an interview

Reasoning path

"Return all ..." means I must enumerate arrangements, so the answer may be exponential.

An arrangement is built piece by piece from a position (the next start index, the next row).

Each new piece can be checked on its own: palindrome, or column and diagonals free. Put that check before the recursive call.

Make the check cheap (sets for N-Queens, an is_pal table if asked) and undo every change after the call.

What to say out loud

  • "I need every partition, so I'll backtrack on where the next piece ends."
  • "I skip a piece that is not a palindrome before recursing, so no work is wasted under it."
  • "For N-Queens there is one queen per row, so I choose a column per row and keep columns, r - c and r + c in sets for O(1) checks."
  • "The output can be exponential: O(n · 2^n) for partitioning, at most n! placements for N-Queens; the recursion uses O(n) extra space."

Common beginner coding mistakes

Palindrome Partitioning

  • Recording path instead of path[:].
  • Forgetting path.pop(), so pieces leak into the next branch.
  • Looping end to len(s) - 1 with slicing, which never takes the last letter.
  • Filling is_pal from the top row down, before is_pal[i+1][j-1] exists.

N-Queens

  • Checking only one diagonal direction.
  • Undoing the sets but not board[r][c] = ".", or the reverse.
  • Appending the board rows by reference instead of building new strings.
  • Trying every square of the board instead of one row at a time, which multiplies the search.

Practice questions

Try each in your head first. Questions 3 and 4 are follow-up variants of this pattern's two problems; their links go to the related problem page.

Practice 1 — Palindrome Partitioning: s = "abba"

Hint: which pieces starting at index 0 are palindromes? Then at index 1?

Answer: [["a","b","b","a"], ["a","bb","a"], ["abba"]], as asserted in the notebook. From start 0 only "a" and "abba" pass; from start 1, "b" and "bb". Step through the method on the Palindrome Partitioning page.

Practice 2 — N-Queens: why is (1, 2) blocked once a queen sits at (0, 1)?

Hint: compute r - c and r + c for both squares.

Answer: (0, 1) has r - c = -1; (1, 2) also has r - c = -1, so they share a \ diagonal and diag already holds -1. Watch the sets change on the N-Queens page.

Practice 3 (follow-up variant) — N-Queens II: return only the number of solutions.

Hint: what does the leaf do now, and do you still need the board?

Answer: keep the same three-set backtracking, but increment a counter at r == n and drop the board entirely; the three sets alone decide safety. For n = 8 it returns 92. The search is the one traced on the N-Queens page.

Practice 4 (follow-up variant) — Palindrome Partitioning II: the minimum number of cuts.

Hint: is enumerating every partition still necessary when only the best one matters?

Answer: no. It asks for a minimum, not all arrangements, so it leaves this pattern: reuse the is_pal table from the notebook's third approach and compute cuts[j] = fewest cuts for s[0..j] with dynamic programming in O(n²), instead of the exponential enumeration. The table is shown filling up on the Palindrome Partitioning page.

Final takeaway

Position, moves, check, choose, recurse, undo. Palindrome Partitioning moves the next piece's end; N-Queens moves the next queen's column. Both win by rejecting a move before recursing on it, and both stay correct only because every choice is undone and every answer is recorded as a copy.
