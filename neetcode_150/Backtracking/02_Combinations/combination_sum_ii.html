40 · Combination Sum II

Each number once, duplicates in the input, no duplicate answers.

The problem, in plain words

Now each number is a single card: you may use a card at most once. Some cards show the same number. List every different combination of cards that adds up to the target, without listing the same combination twice.

Example: [10, 1, 2, 7, 6, 1, 5], target 8 → [[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]].

The three solutions below are traced on the small input [2, 1, 2], target 3 → [[1, 2]]: the two 2s are exactly the duplicate trap. Sorted, it is [1, 2, 2].

Solution 1 — Brute force: every subset, then a set removes repeats

Sort, then say yes or no to every card. Whenever the sum hits the target, put the combination (as a tuple) into a set. [1, 2] is built twice (once with each 2); the set keeps one copy, but both were built.

Solution 2 — Include or exclude, but exclude a whole run of equal values

Same yes/no tree, with one fix. When you say no to a value, also say no to every copy of it right after (jump past the run). Saying no to the first 2 and then yes to the second 2 would only rebuild what the yes-branch already built.

Solution 3 — The smart way: start-index loop, skip sibling duplicates, recurse with i + 1

The Combination Sum loop with two changes. Recurse with i + 1, so each card is used once. And inside one call's loop, skip a value equal to the previous one (i > start and c[i] == c[i-1]): as the first number of the rest of the path, the second 2 would grow exactly the same subtree as the first 2.

When you'd use this

See "may contain duplicates", "each number used once" and "no duplicate combinations"? Sort, recurse with i + 1, and skip a value equal to its previous sibling.
