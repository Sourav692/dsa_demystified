Combinations

List every combination that meets a goal by building it one choice at a time: choose, explore, undo. A start index that only moves forward means each set is built in exactly one order, the recursion argument (i or i + 1) decides whether a choice can be reused, and sorting lets you skip duplicates and stop a loop the moment a choice is too big.

Core idea: start-index loop, choose / explore / undo Method 1: Combination Sum (reuse, break) Method 2: Combination Sum II (sort, skip duplicates, i + 1) Interactive traces synced to code

Problems in this pattern: Combination Sum · Combination Sum II · Letter Combinations of a Phone Number · Generate Parentheses · pattern notes (README)

Canonical example

Combination Sum, candidates = [2, 3, 6, 7], target = 7. Every call of the start-index search, with the remainder in each box:

Answer = [[2, 2, 3], [7]]

Why this pattern matters

Spending an exact budget

Which bundles of items, coins or tasks add up to exactly a target? Combination Sum is that question with reuse; Combination Sum II is it with a limited stock of each item.

Enumerating every configuration

One option per slot from a fixed menu: keypad words, test-case matrices, product variants. Letter Combinations is the cleanest version: nothing to prune, every leaf is an answer.

Generating only valid structures

Balanced brackets, valid expressions, legal moves. Generate Parentheses shows how a rule checked on the prefix prunes every invalid branch before it is built.

Instructor note: all four problems run the same 6-line loop. What changes is only the menu of choices at each level, whether the recursion passes i or i + 1, and which branches are pruned. Learn the loop once, then learn the knobs.

What is the Combinations pattern?

Simple definition

A depth-first search over a tree of choices. Each node is a partial answer held in one shared path list; each edge appends one choice. You choose (path.append), explore (recurse), then un-choose (path.pop()) so the next sibling starts clean. When the goal is met you save a copy, path[:].

The tell in a problem statement

"Return all combinations / all possible strings", "each number may be chosen an unlimited number of times" or "used once", "may contain duplicates, but the answer must not", "all well-formed ...". Order of the chosen items does not matter, and you must list the answers, not count them.

Beginner shortcut: a combination is decided by which items it holds, not their order. So never look back: each call only considers choices from start onward. Then [2, 3] is built and [3, 2] never is, with no set needed.

Step-by-step thinking process

1

Spot "list all"

The output is every combination, so the work is at least the size of the answer. Backtracking is the tool.

2

Name the menu per level

Candidates from start onward, the letters of digits[i], or ( / ).

3

Set the reuse and duplicate rules

Reuse allowed: recurse with i. Once only: i + 1. Duplicates in the input: sort, then skip a value equal to its previous sibling.

4

Prune and record

Stop branches that can't succeed (break on overshoot, prefix rules), and save path[:] when the goal is met.

How the input becomes a tree of choices

The input is just a list and a target. The algorithm never builds the tree as a data structure: the tree is the shape of the recursive calls. Each call is a node holding (start, remain); the shared path list is the route from the root to that node.

Input

candidates = [2, 3, 6, 7] target = 7
→

Tree of calls

root (start=0, remain=7) +2 -> (start=0, remain=5) +2 +2 -> (start=0, remain=3) +2 +2 +3 -> remain 0: save [2, 2, 3] +7 -> (start=3, remain=0): save [7]

Sort the candidates

Sorted order makes "too big" final: once candidates[i] > remain, every later candidate is too big as well.

The root call holds the whole target

backtrack(0, 7, []): nothing chosen, 7 still to reach, every candidate allowed.

Each edge subtracts one candidate

Choosing candidates[i] creates a child with remain - candidates[i] and start = i (reuse) or i + 1 (once only).

Leaves end the branch

remain == 0 is an answer: save path[:]. A candidate bigger than remain is a dead branch: break.

Critical point: there is only one path list for the whole search. That is why every append needs a matching pop, and why a saved answer must be a copy: res.append(path) would store a reference that later pops empty out.

Method 1: start-index loop with reuse and break (Combination Sum)

The template itself, line for line from the notebook's combination_sum_start_index. Sort, loop from start, break on the first candidate that overshoots, choose, recurse with i so the candidate can be reused, pop. Traced on candidates = [2, 3, 6, 7], target = 7: 10 calls and 7 breaks.

def combination_sum_start_index(candidates: List[int], target: int) -> List[List[int]]: candidates = sorted(candidates) # sorting lets us stop early when a number is too big res = [] def backtrack(start, remain, path): # remain = target left to reach; path = chosen so far if remain == 0: res.append(path[:]) # exact hit -> save a COPY of the combination return for i in range(start, len(candidates)): # only consider candidates from `start` onward if candidates[i] > remain: break # sorted -> everything after is also too big path.append(candidates[i]) # choose this candidate backtrack(i, remain - candidates[i], path) # i (not i+1) allows reusing it path.pop() # un-choose it (backtrack) and try the next backtrack(0, target, []) return res

Key mental model

Each call answers "which numbers, from start onward, finish the job of reaching remain?". Passing i keeps the current number on the menu; everything left of start has already been fully explored by an earlier sibling.

Common mistake

Recursing with 0 instead of i: the search would rebuild [2, 3, 2] and [3, 2, 2] after [2, 2, 3]. Recursing with i + 1 instead: [2, 2, 3] disappears because 2 can't be reused.

Why sort first

Without sorting, a too-big candidate only says something about itself, so the loop must continue through all the rest. Sorted, the first overshoot ends the loop: at step 5 one comparison (2 > remain 1) rules out 3, 6 and 7 without looking at them.

Method 2: once only, with duplicates in the input (Combination Sum II)

Two edits to Method 1, from the notebook's combination_sum2_start_index. Recurse with i + 1, so each element is used at most once. And skip a sibling duplicate: if i > start and candidates[i] == candidates[i - 1]: continue. Traced on candidates = [2, 5, 2, 1, 2] (sorted [1, 2, 2, 2, 5]), target = 5; the skip fires 6 times.

def combination_sum2_start_index(candidates: List[int], target: int) -> List[List[int]]: candidates = sorted(candidates) # sort: enables `break` AND puts duplicates side by side res = [] def backtrack(start, remain, path): if remain == 0: res.append(path[:]) # exact hit -> save a COPY return for i in range(start, len(candidates)): if candidates[i] > remain: break # sorted -> nothing later fits either if i > start and candidates[i] == candidates[i - 1]: continue # SKIP sibling duplicate: same value, same subtree path.append(candidates[i]) backtrack(i + 1, remain - candidates[i], path) # `i + 1`: each element at most once path.pop() backtrack(0, target, []) return res

Key mental model

Siblings in the tree are "the next number of the combination". Two siblings with the same value would grow identical subtrees, so only the first one is explored. Going deeper with an equal value is still allowed: that is how [1, 2, 2] uses two 2s.

Common mistake

Writing i > 0 instead of i > start. Then the first 2 at a deeper level is skipped because it equals the 2 before it, and answers like [1, 2, 2] or [1, 1, 6] vanish.

Why not dedupe with a set?

A set of tuples gives the right output, but every duplicate is still built first. On [1] * n with target = n // 2 the notebook measures the set version growing about 4x per +2 elements, while this loop barely changes.

Edge cases you should test

Case A: every candidate is bigger than the target

combination_sum([5, 7], 3)

Answer = []

The first loop iteration breaks: 5 > 3. No call ever reaches remain == 0, so res stays empty.

Case B: no digits

letter_combinations("")

Answer = []

Return [], not [""]. Without the guard, the base case fires at once (i == len(digits) == 0) and saves one empty string.

Case C: every value is the same

combination_sum2([1, 1, 1, 1], 2)

Answer = [[1, 1]]

Six pairs of positions sum to 2, but they are all the same combination. The sibling-skip explores one 1 per level, so it builds [1, 1] exactly once.

Case D: one pair of brackets

generate_parenthesis(1)

Answer = ['()']

At the root only ( is allowed (close < open is false); after it only ) is allowed (open == n).

Case E: a single candidate used many times

combination_sum([3], 9)

Answer = [[3, 3, 3]]

Only works because the recursion passes i: the path is 3, 3, 3. With i + 1 the answer would wrongly be [].

How to derive this in an interview

Reasoning path

"Return all combinations": the answer can be exponential, so an exhaustive search is acceptable. Backtracking.

Order doesn't matter, so only move forward: a start index.

Reuse allowed? Recurse with i. Once only? i + 1. Duplicate values? Sort and skip equal siblings.

Prune what can't work (sorted break, prefix rules), and save path[:] at the goal.

What to say out loud

  • "We need every combination, so I'll backtrack: append a choice, recurse, pop it."
  • "A start index means I never revisit earlier candidates, so each set is generated once without a set."
  • "Because reuse is allowed I recurse with i; in the once-only version it's i + 1, and I skip candidates[i] == candidates[i - 1] when i > start."
  • "I sort so I can break as soon as a candidate exceeds the remainder. The time is exponential, bounded by the number of answers; space is the recursion depth."

Common beginner coding mistakes

Method 1: Combination Sum

  • res.append(path) without a copy: every saved entry is the same list, and it ends up empty.
  • Forgetting path.pop(): choices leak into sibling branches.
  • Recursing with i + 1 (no reuse) or 0 (duplicate orderings).
  • break on an unsorted list: skips candidates that would still fit.

Method 2: Combination Sum II

  • Skipping duplicates without sorting first: equal values aren't neighbours.
  • i > 0 instead of i > start: loses [1, 1, 6]-style answers.
  • Recursing with i out of habit: reuses a single card.
  • Deduplicating with a set at the end: correct output, exponential wasted work.

Final takeaway

Loop from start, choose, recurse, pop. Pass i to allow reuse and i + 1 to forbid it; sort to break on overshoot and to skip equal siblings; replace the candidate list with whatever menu each level offers (letters of a digit, an open or a close bracket). Four problems, one loop.
