39 · Combination Sum

Every way to reach the target, reusing numbers as often as you like.

The problem, in plain words

You have coins of a few values and unlimited copies of each. List every different handful of coins that adds up to exactly the target. A handful is a set with counts: 2 + 2 + 3 and 3 + 2 + 2 are the same handful.

Example: candidates = [2, 3, 6, 7], target = 7 → [[2, 2, 3], [7]].

combinations

Both solutions below are backtracking; they are traced on the smaller input [2, 3, 5], target 5 → [[2, 3], [5]].

Solution 1 — Include or exclude each candidate

Stand on one candidate at a time and make a yes/no decision. Yes: put it in the path and stay on it (it may be used again). No: move on to the next candidate for good. Save the path whenever nothing is left.

found so far

Speed & memory: every call makes at most two more calls, so the tree is exponential: about O(2^(T/M + N)) (T = target, M = smallest candidate, N = number of candidates); the path is at most T/M + N deep. Here it needs 17 calls.

Solution 2 — The smart way: start-index loop, sort, break (the pattern template)

Sort the candidates. Each call loops over the candidates from start onward, never going back, so 3 + 2 can't be built after 2 + 3. Recurse with i (not i + 1) so a number can be reused. The moment a candidate is bigger than what is left, break: everything after it is bigger too.

Speed & memory: still exponential in the worst case, O(N^(T/M + 1)), because the answer list itself can be that long; the path is at most T/M deep. The break cuts dead branches: here it needs 6 calls instead of 17.

When you'd use this

See "all combinations that sum to" and "may be chosen an unlimited number of times"? Use the start-index loop and recurse with i. If each number may be used once, recurse with i + 1 (Combination Sum II).
