Prefix Suffix

When every answer means "combine everything except position i", split the rest of the array into the part left of i and the part right of i. One pass builds the left aggregate, a second pass walks back with the right aggregate, and each slot costs one operation instead of a rescan.

Core idea: left part × right part Method 1: two-pass prefix × suffix Method 2: the brute force it replaces Interactive traces synced to code

Problem in this pattern: Product of Array Except Self · pattern notes (README)

Canonical example

Product of Array Except Self, nums = [1, 2, 3, 4]. For index 2 the answer is (left of it) × (right of it).

Answer = [24, 12, 8, 6]

Why this pattern matters

"Everything except me" answers

Each position needs an aggregate of all the others. Recomputing it per position costs O(n) each, O(n²) total. Two running aggregates bring it to O(n).

When you cannot "subtract one out"

For sums you could take the total and subtract nums[i]. For products that needs division, which the problem forbids and which breaks on a zero. Prefix and suffix never remove anything, so they always work.

Range queries in general

The additive cousin, prefix sums, turns every "sum of nums[l..r]" query into one subtraction after one O(n) pass.

Instructor note: the whole pattern is one sentence: "the answer at i is (everything before i) combined with (everything after i)". Once you say that out loud, the two passes write themselves.

What is the prefix suffix pattern?

Simple definition

A prefix aggregate at i combines nums[0..i-1]; a suffix aggregate combines nums[i+1..]. Both can be carried in a single running variable: walking forward, the prefix gains one element per step; walking backward, the suffix does the same. Combine the two at each index and you have "everything except nums[i]".

The tell in a problem statement

"Product (or sum) of all elements except nums[i]", "without using division" next to an O(n) requirement, an answer that depends on what lies to the left and to the right of each index, or many range-sum queries over a fixed array.

Beginner shortcut: the order of two lines carries the whole "except" part. Store first (out[i] = prefix), then extend (prefix *= nums[i]). Storing first means the stored product has not seen nums[i] yet.

Step-by-step thinking process

1

Split around i

"All except nums[i]" = (everything left of i) × (everything right of i).

2

Left pass

Walk left to right with prefix = 1. Write out[i] = prefix, then prefix *= nums[i].

3

Right pass

Walk right to left with suffix = 1. Do out[i] *= suffix, then suffix *= nums[i].

4

Return out

Every slot now holds left × right. Two linear passes, one extra variable at a time.

How the input becomes left and right products

The input is a plain list. The algorithm never stores a second list of its own: conceptually there are two helper arrays, L[i] (product of everything before i) and R[i] (product of everything after i), and the answer is L[i] × R[i]. The optimal code writes L straight into out and replaces R with a single running number.

Input list

nums = [1, 2, 3, 4]
→

Left and right products

L = [1, 1, 2, 6] # product before i R = [24, 12, 4, 1] # product after i out = [24, 12, 8, 6] # L[i] * R[i]

Start with the empty product 1

Nothing lies left of index 0, so L[0] = 1: multiplying by 1 changes nothing. The same holds for R[3].

Each L entry extends the previous one

L[i] = L[i-1] × nums[i-1]: 1, then 1 × 1 = 1, then 1 × 2 = 2, then 2 × 3 = 6.

Each R entry extends the one to its right

R[i] = R[i+1] × nums[i+1]: 1, then 1 × 4 = 4, then 4 × 3 = 12, then 12 × 2 = 24.

Multiply pairwise

[1 × 24, 1 × 12, 2 × 4, 6 × 1] = [24, 12, 8, 6].

Critical point: since R[i] is only ever needed once, at the moment the right-to-left pass reaches i, it can live in one variable (suffix). And L can live in out itself. That is how the two passes get to O(1) extra space.

Method 1: two-pass prefix × suffix (Product of Array Except Self)

The notebook's product_except_self_optimal, line for line. The first loop leaves out = [1, 1, 2, 6] (the L array). The second loop carries suffix from the right and multiplies it into each slot.

def product_except_self_optimal(nums: List[int]) -> List[int]: n = len(nums) out = [1] * n prefix = 1 # running product of everything to the LEFT for i in range(n): out[i] = prefix # store product of all elements before i prefix *= nums[i] # extend the running left-product suffix = 1 # running product of everything to the RIGHT for i in range(n - 1, -1, -1): # sweep right to left out[i] *= suffix # multiply in the product of all elements after i suffix *= nums[i] # extend the running right-product return out

Key mental model

After the left pass, slot i holds the blue half of its answer. The right pass brings the green half: when it reaches i, suffix is exactly the product of the cells to the right of i.

Common mistake

Swapping lines 6 and 7 (extend first, then store). Then out[i] includes nums[i] and the "except self" part is gone: the left pass would produce [1, 2, 6, 24].

Why the output array is enough

The left products are needed only once each, in the right pass, at the same index. So they can sit in out until then, and the suffix never needs more than one variable. Extra space: O(1) besides the output.

Method 2: the brute force it replaces

The notebook's product_except_self_brute. For every index it starts a fresh product p = 1 and multiplies in every other element. Correct, but it forgets everything between indices: the product of 3 × 4 is recomputed for i = 0, i = 1 and again later. Each step below is one full pass of the inner loop.

def product_except_self_brute(nums: List[int]) -> List[int]: n = len(nums) out = [1] * n for i in range(n): # compute the answer for each position i p = 1 for j in range(n): # multiply together every OTHER element if j != i: # skip the element at i itself p *= nums[j] out[i] = p return out

Key mental model

Brute force multiplies n - 1 numbers for each of n slots: n(n - 1) multiplications. Method 1 does three per index: 3n. At n = 4 both happen to be 12; at n = 8000 it is about 64 million against 24 thousand.

Common mistake

Reaching for the "total divided by nums[i]" shortcut instead. The problem forbids division, and with a zero in the array it divides by zero unless you count zeros first (the notebook's division approach does exactly that).

What the measurement shows

In the notebook's benchmark, doubling n multiplied the brute force time by about 4x (quadratic) and Method 1's by about 2x (linear).

Edge cases you should test

Case A: the smallest allowed input

nums = [2, 3]

Answer = [3, 2]

The left pass gives [1, 2]; the right pass multiplies in suffixes 3 and 1. The empty products at both ends are why prefix and suffix start at 1.

Case B: exactly one zero

nums = [-1, 1, 0, -3, 3]

Answer = [0, 0, 9, 0, 0]

After the left pass out = [1, -1, -1, 0, 0]. Every product that contains the 0 is 0; only the zero's own slot gets (-1 × 1) × (-3 × 3) = 9. No special case in the code.

Case C: two or more zeros

nums = [0, 4, 0]

Answer = [0, 0, 0]

Every slot's "everything else" contains at least one zero. The division approach needs a zeros > 1 branch for this; the two passes handle it unchanged.

Case D: negative numbers

nums = [-2, -3, 4]

Answer = [-12, -8, 6]

Signs just multiply through. Nothing in the algorithm compares values, so negatives need no care.

How to derive this in an interview

Reasoning path

Brute force first: for each i, multiply the others. O(n²). Where is the repeated work?

Division would fix it, but it is not allowed and fails on zeros.

Split "all except i" into left of i and right of i. Each side is a running product.

Store the left products in out, then sweep back with a single suffix.

What to say out loud

  • "The answer at i is the product of everything to its left times everything to its right, so I don't need division."
  • "A left-to-right pass writes the left products into the output; I store before I multiply so nums[i] is excluded."
  • "A right-to-left pass multiplies in a running suffix product."
  • "Two passes: O(n) time, O(1) extra space besides the output, and zeros need no special case."

Common beginner coding mistakes

Two-pass prefix × suffix

  • Extending before storing (prefix *= nums[i] first), so each answer includes nums[i].
  • Starting prefix or suffix at 0 instead of 1: every product becomes 0.
  • Writing out[i] = suffix in the second pass instead of out[i] *= suffix, which throws away the left products.
  • Off by one in the reverse range: it is range(n - 1, -1, -1), which ends at index 0.

Brute force and division

  • Forgetting if j != i, so every product includes the element itself.
  • Not resetting p = 1 for each i.
  • Using division without counting zeros: one zero means only its slot is nonzero, two or more mean all zeros.
  • Using / instead of // in Python and returning floats.

Practice questions

Practice 1 — Product of Array Except Self: nums = [-1, 1, 0, -3, 3]

Hint: which slots have the zero somewhere in "everything else"?

Answer: [0, 0, 9, 0, 0]. Only index 2 (the zero itself) avoids it: (-1 × 1) × (-3 × 3) = 9. This is one of the notebook's test cases; step through the passes on the Product of Array Except Self page.

Practice 2 (variant: handling zeros) — what do the two passes return for [0, 4, 0], and what extra code would division need?

Hint: after the left pass, out = [1, 0, 0].

Answer: [0, 0, 0], with no extra code. Division would need to count zeros and return all zeros when there are two or more, as the notebook's division approach does. Compare with the problem page.

Practice 3 (variant: the O(n)-space version) — for [1, 2, 3, 4], write out L and R, then explain how Method 1 removes both arrays.

Hint: L[i] is the product before i, R[i] the product after i.

Answer: L = [1, 1, 2, 6], R = [24, 12, 4, 1], answer [24, 12, 8, 6]. Method 1 writes L into out and computes each R[i] on the fly as suffix, used once and then extended. See the left-pass and right-pass tables on the problem page.

Practice 4 (variant: prefix sums for range queries) — nums = [-2, 0, 3, -5, 2, -1], answer sum(nums[2..5]) in O(1) after one pass.

Hint: build P with P[0] = 0 and P[k + 1] = P[k] + nums[k]; then sum(nums[l..r]) = P[r + 1] - P[l].

Answer: P = [0, -2, -2, 1, -4, -2, -3], so the sum is P[6] - P[2] = -3 - (-2) = -1 (check: 3 - 5 + 2 - 1 = -1). Same running aggregate as the left pass of Product of Array Except Self, with + and 0 instead of × and 1. This is LeetCode 303, Range Sum Query - Immutable.

Final takeaway

Everything except i = everything before i combined with everything after i. Build the left side in one forward pass (store, then extend), bring in the right side in one backward pass, and every answer costs one multiplication. No division, no zero cases, O(n) time and O(1) extra space.
