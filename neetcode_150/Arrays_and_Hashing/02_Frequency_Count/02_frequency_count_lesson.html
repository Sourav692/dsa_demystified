Frequency Count

Walk the input once and tally how many times each key appears in a hash map. Then answer the question by reading the tallies instead of searching the input again: compare two tallies, use a tally as a key, rank by tallies, or multiply them.

Core idea: count[key] = count.get(key, 0) + 1 Method 1: Valid Anagram Method 2: Group Anagrams Interactive traces synced to code

Problems in this pattern: Valid Anagram · Group Anagrams · Top K Frequent Elements · Detect Squares · pattern notes (README)

Canonical example

Valid Anagram, s = "anagram", t = "nagaram"

Answer = True (counts {a:3, n:1, g:1, r:1, m:1} match)

Why this pattern matters

"Same parts, any order"

Anagrams, permutations, shopping baskets with the same items: two things are equal as soon as their counts are equal, whatever the order.

Ranking by popularity

Most-played songs, most common error codes, top k search terms: count first, then rank by the count.

Counting combinations fast

When equal items are still different choices, the number of ways is a product of counts. A count map gives each factor in one lookup.

Instructor note: the counting loop is the same five lines in all four problems of this pattern. What you learn per problem is only the last step: what to do with the counts once you have them.

What is a frequency count?

Simple definition

A hash map (Python dict) from each key to the number of times it appeared. One pass over the input builds it, with an O(1) average update per item, so the whole build is O(n). collections.Counter is the same thing, ready-made.

The tell in a problem statement

"Anagram", "permutation of", "same characters"; "group the words that..."; "most frequent", "top k"; "duplicates are treated as different", "how many ways". Order doesn't matter, but how many of each does.

Beginner shortcut: if you catch yourself sorting just to put equal items next to each other, or scanning the input again to count something, a count map built once usually replaces both.

Step-by-step thinking process

1

Spot "how many"

The answer depends on how many of each item there are, not where they are.

2

Choose the key

What is being counted: a letter, a number, a point (x, y). It must be hashable (use a tuple, not a list).

3

Tally in one pass

count[key] = count.get(key, 0) + 1 for every item: O(n) total.

4

Read the counts

Compare them, use them as a key, bucket by them, or multiply them. That last step is the whole problem-specific part.

How the input becomes a count map

The input is a sequence (a string, a list of numbers, a stream of points). The map keeps only what the question needs: each distinct key once, with a number beside it. Position and order are thrown away on purpose.

Input sequence

s = "anagram" # 7 letters, order matters here
→

Count map

{'a': 3, 'n': 1, 'g': 1, 'r': 1, 'm': 1}

Read a: not in the map yet

count.get('a', 0) returns 0, so a starts at 1.

Read n, then a again

n starts at 1; a already has an entry, so it goes up to 2.

Read g, r, a, m

Two new keys and one more a (now 3), then m starts at 1.

Done: 7 letters became 5 entries

Any other word with the same 5 counts is an anagram of "anagram", in any order.

Critical point: the map size is the number of distinct keys, not the input length. For lowercase letters that is at most 26, which is why Valid Anagram's count version is O(1) extra space.

Method 1: tally, then spend (Valid Anagram)

The template on the canonical problem, line for line from the notebook's is_anagram_count. Tally every letter of s. Then walk t and "spend" one count per letter, deleting a key when it reaches 0. If t asks for a letter that is not there, stop early. If the map is empty at the end, every count matched exactly.

def is_anagram_count(s: str, t: str) -> bool: # Quick reject: different lengths can never be anagrams. if len(s) != len(t): return False count = {} # letter -> how many times it appears in s for c in s: # step 1: tally every letter of the first word count[c] = count.get(c, 0) + 1 # add one to this letter's running total for c in t: # step 2: "spend" one of each letter for word t if c not in count: # t needs a letter that s never had -> not anagram return False count[c] -= 1 # use up one occurrence of this letter if count[c] == 0: # exhausted this letter -> drop it from the map del count[c] return len(count) == 0 # anagram only if every letter was used up exactly

Key mental model

The map is a recipe. Tallying s writes the recipe; reading t cooks from it. An anagram uses every ingredient exactly, with nothing missing and nothing left.

Common mistake

Only checking that every letter of t is found. With s = "ab", t = "a" that passes, yet b:1 is left over. The final len(count) == 0 (or the length check up front) catches it.

Why a hash map

Each get, -= 1 and del is O(1) on average, so the two loops are O(n) in total. Sorting both words instead costs O(n log n).

Method 2: the count becomes the key (Group Anagrams)

Same tally, but now per word, and the finished tally is not compared: it is frozen into a tuple of 26 numbers and used as the key of a second map. All anagrams produce the same tuple, so they land in the same list. Code from the notebook's group_count, traced on ["eat","tea","tan","ate","nat","bat"]. The state boxes show only the non-zero letters of the 26 counts.

def group_count(strs: List[str]) -> List[List[str]]: groups = defaultdict(list) # fingerprint -> list of words for w in strs: counts = [0] * 26 # how many of each letter a..z this word has for c in w: counts[ord(c) - ord("a")] += 1 # tally the letter (a=0, b=1, ...) groups[tuple(counts)].append(w) # a tuple is hashable, so it works as a dict key return list(groups.values())

Key mental model

Two maps stacked: an inner tally per word (26 slots), and an outer map from "tally" to "words with that tally". The inner count is the fingerprint; the outer map is the filing cabinet.

Common mistake

Using the list counts itself as the key: lists are mutable, so Python refuses to hash them (TypeError: unhashable type: 'list'). Freeze it with tuple(counts).

Count key vs sorted key

The count key is O(k) per word, the sorted key O(k log k). The notebook measured both at about 2x per doubling on 4-letter words, with the sorted key faster in Python at that length.

Edge cases you should test

Case A: t needs a letter s never had

s = "rat", t = "car"

Valid Anagram = False

The tally is {r:1, a:1, t:1}. The very first letter of t, c, is not in the map, so line 10 returns False before anything is spent.

Case B: different lengths

s = "a", t = "ab"

Valid Anagram = False

The length check on line 3 rejects it without building a map. Different lengths can never have equal counts.

Case C: empty input

s = "", t = "" and strs = [""]

Valid Anagram = True · Group Anagrams = [[""]]

Two empty tallies are equal. The empty word's key is 26 zeros, which is a valid key, so it gets its own group (the notebook checks 1 group).

Case D: duplicates are different choices

Detect Squares: add (0,0) twice, (1,0) twice, (0,1) once, then count((1,1))

count = 2 × 2 × 1 = 4

The diagonal (0,0) has 2 copies, corner (1,0) has 2, corner (0,1) has 1. Every pairing is a different square, so the counts multiply. Deduplicating would give 1.

How to derive this in an interview

Reasoning path

The answer does not depend on order, only on how many of each item there are.

So build a map from item to count in one pass: O(n).

Ask what the question does with counts: compare, group, rank, or multiply.

Pick the matching read-out: compare maps, tuple key, buckets by frequency, product of lookups.

What to say out loud

  • "Order doesn't matter here, only the counts, so I'll build a frequency map in one pass."
  • "Dict updates are O(1) on average, so building it is O(n)."
  • "Sorting would also work but costs O(n log n); counting avoids the log factor."
  • "For lowercase letters the map has at most 26 keys, so the extra space is O(1)."

Common beginner coding mistakes

Valid Anagram (compare counts)

  • Checking only that every letter of t exists in s, and never checking for leftovers.
  • Comparing the words with set(s) == set(t): that ignores counts, so "aab" and "abb" look equal.
  • Writing count[c] += 1 on a plain dict without a default: KeyError on the first new letter.
  • Assuming 26 slots when the input may contain other characters.

Group Anagrams and the rest

  • Using a list as a dict key instead of a tuple.
  • Grouping by the raw word, which never groups anything.
  • Top K: sorting every count (O(n log n)) when a heap or buckets are enough.
  • Detect Squares: forgetting px != qx, which counts zero-area "squares".

Practice 1 — Group Anagrams: strs = ["eat","tea","tan","ate","nat","bat"]. How many groups, and which key does "nat" share?

Hint: write the non-zero letter counts of each word.

Answer: 3 groups. "nat" has counts {a:1, n:1, t:1}, the same key as "tan". Step through it: Group Anagrams.

Practice 2 — Top K Frequent Elements: nums = [1,1,1,2,2,3], k = 2. What do the buckets look like?

Hint: count first, then put each value in the bucket whose index is its count.

Answer: counts {1:3, 2:2, 3:1}, buckets [[], [3], [2], [1], [], [], []]. Reading from the top: 1, then 2, so the answer is [1, 2]. See Top K Frequent Elements.

Practice 3 — Detect Squares: pins at (3,10), (11,2), (3,2), (11,2). What does count((11,10)) return?

Hint: only (3,2) is a diagonal partner of the query. How many pins sit on each of the other two corners?

Answer: 2. Diagonal (3,2) has 1 pin, corner (11,2) has 2, corner (3,10) has 1: 1 × 2 × 1. Walk through it on Detect Squares.

Practice 4 — Follow-up variant of Valid Anagram: what changes if the input can contain any Unicode character?

Hint: which version assumes a fixed alphabet?

Answer: nothing in Method 1. Its dict accepts any character as a key; only the extra-space bound changes from O(1) to O(distinct characters). A fixed array of 26 slots (like Group Anagrams' counts) would break. This variant is not one of the notebook's tests; compare with Valid Anagram.

Final takeaway

Count once, then read the counts. One pass with count[key] = count.get(key, 0) + 1 builds the map. Valid Anagram compares the counts, Group Anagrams uses them as a key, Top K ranks by them, and Detect Squares multiplies them. Same loop, four different read-outs.
