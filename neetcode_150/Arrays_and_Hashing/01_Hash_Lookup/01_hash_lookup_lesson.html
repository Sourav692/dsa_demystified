Hash Lookup

Many brute forces are a nested loop whose inner loop only searches for a value. A hash set or hash map answers "is this value here?" in O(1) on average, so remember what you have seen, ask the memory instead of rescanning, and the nested loop becomes one pass.

Core idea: if key in seen before seen.add(x) Method 1: Contains Duplicate (set) Method 2: Two Sum (dict, complement) Interactive traces synced to code

Problems in this pattern: Contains Duplicate · Two Sum · Valid Sudoku · Longest Consecutive Sequence · pattern notes (README)

Canonical example

Contains Duplicate, nums = [1, 2, 3, 1]

Answer = True (the second 1 is already in seen)

Why this pattern matters

Deduplication everywhere

"Have I processed this order id / URL / username before?" is the same question as Contains Duplicate, asked millions of times. A set answers each one without scanning history.

Matching pairs

Reconciling payments against invoices, or finding two items that hit a budget, is Two Sum: for each item, look up the partner it needs.

Rules per group

"No duplicate seat per row, no duplicate badge per team": give each group its own set, as Valid Sudoku does for rows, columns and boxes.

Instructor note: this is the first optimisation to try in almost every array problem. Whenever the brute force has an inner loop that only looks for something, ask "could a set or dict find it in one step?"

What is hash lookup?

Simple definition

Walk the input once. For each item, compute the key whose presence answers the question (the item itself, its complement target - x, its neighbour x - 1), look the key up in a hash set or map, and only then record the current item. A hash lookup costs O(1) on average, so the whole walk is O(n).

The tell in a problem statement

"Contains duplicate", "all unique?", "find two numbers that add up to", "no repeats in each row / column / box", "longest run of consecutive numbers in O(n)". Or: the brute force is a nested loop whose inner loop only searches for a value.

Beginner shortcut: ask "what single value, if I had already seen it, would give me the answer right now?" That value is your lookup key. Check for it first, then remember the current item.

Step-by-step thinking process

1

Write the brute force

Usually two nested loops. Notice that the inner loop only searches for one value.

2

Name the key

What would the inner loop find? x itself, target - x, the digit in this row, x - 1.

3

Pick the memory

A set if you only need "present or not"; a dict if the answer needs more (an index). One per group if there are groups.

4

Check, then record

Look the key up first; if it is absent, add the current item. Reversing the order lets an item match itself.

How the input becomes a hash set

The array stays where it is. Next to it we build a second structure, seen, one item at a time. A hash set is an internal table of slots. To store or find x, Python computes hash(x) and jumps to the slot that number points at. It never walks through the other slots, which is why x in seen does not slow down as the set grows.

Input array

nums = [1, 2, 3, 1]
→

Hash set after three steps (simplified: 8 slots)

slot: 0 1 2 3 4 5 6 7 value: . 1 2 3 . . . . (slot = hash(x) mod 8; hash(1) == 1 for small ints)

Read 1

Slot 1 is empty, so 1 is new. Store it in slot 1.

Read 2, then 3

Slots 2 and 3 are empty. Store each one.

Read 1 again

Jump to slot 1: it already holds 1. One check, no scan: duplicate found.

Same idea with a dict

Two Sum stores value → index. The key is hashed exactly like a set element; the slot also keeps the index.

Critical point: the slot picture is simplified. Real tables grow as they fill and resolve collisions (two keys wanting one slot) by probing other slots, so a lookup is O(1) on average, not guaranteed. Compare a list: x in nums checks every element, O(n).

Method 1: hash set membership (Contains Duplicate)

The template in its purest form: the lookup key is the value itself. Code taken line for line from the notebook's contains_duplicate_set, traced on nums = [1, 2, 3, 1].

def contains_duplicate_set(nums: List[int]) -> bool: seen = set() # values we've already encountered for x in nums: if x in seen: # already met this value -> duplicate return True seen.add(x) # otherwise remember it and continue return False

Key mental model

The set is a notebook of everything already passed. Each new element asks the notebook one question and gets an answer in one step, instead of re-reading the array behind it.

Common mistake

Using a list for seen. x in some_list walks the list, so the "one pass" is secretly O(n²), the same as the brute force.

Why a hash set

The notebook measures it: on all-distinct input the pairwise brute force grew about 3 to 4x per doubling of n, the set version about 2x. You pay O(n) memory for that.

Method 2: look up the complement (Two Sum)

Same loop, different key. The value that would finish a pair with x is need = target - x, so look that up. The answer needs indices, so the memory is a dict from value to index. Code from the notebook's two_sum_optimal, traced on nums = [3, 2, 4], target = 6.

def two_sum_optimal(nums: List[int], target: int) -> List[int]: seen = {} # value -> index, for numbers we've already passed for i, x in enumerate(nums): need = target - x # the partner that would complete the pair if need in seen: # have we already passed that partner? return [seen[need], i] # yes -> we found the pair seen[x] = i # no -> remember x so a future number can find it return []

Key mental model

Each number arrives asking "is my partner already here?" The pair is found when its second member arrives, because the first one was stored on the way past.

Common mistake

Storing seen[x] = i before the lookup. At step 1, x = 3 and need = 3: if 3 were already stored, the code would return [0, 0], using one element twice.

Why a dict, not a set

The problem asks for indices. A set could say "the partner exists" but not where. The dict keeps the index next to the key at no extra lookup cost.

Edge cases you should test

Case A: Two Sum with equal values

nums = [3, 3], target = 6

Answer = [0, 1]

At i = 0 the dict is empty, so 3 is stored. At i = 1, need = 3 is found at index 0. Check-before-store is what makes this work without pairing an element with itself.

Case B: Contains Duplicate with one element

nums = [1]

Answer = False

One lookup in an empty set, one insert, the loop ends, return False.

Case C: Valid Sudoku, repeat that only a box sees

A 2 at (3, 3) and another 2 at (5, 5), rest of the board empty.

Answer = False

Different rows, different columns, but both in box (1, 1). Checking only row and column sets misses it. Walk through the 4×4 version on the Valid Sudoku page.

Case D: Longest Consecutive Sequence with repeats

nums = [5, 5, 5] and nums = []

Answers = 1 and 0

set(nums) removes the repeats, so the run [5] is counted once. The empty list never enters the loop and returns the initial best = 0.

How to derive this in an interview

Reasoning path

State the brute force: for each element, scan the others. O(n²).

Notice the inner scan only looks for one specific value: x, target - x, the same digit in this row.

A hash set finds a value in O(1) on average, so keep one of everything already passed.

Look up first, record second. Pick dict if the answer needs more than yes or no.

What to say out loud

  • "The brute force compares every pair, O(n²). Its inner loop is just a search, so I'll replace it with a hash set lookup."
  • "For each element I ask the set for the value that would answer the question, and only then add the element, so it can't match itself."
  • "I need the index back, so I'll use a dict from value to index."
  • "One pass with O(1) average lookups: O(n) time, O(n) extra space. If memory were tight I'd sort instead, O(n log n)."

Common beginner coding mistakes

Membership (Contains Duplicate, Valid Sudoku)

  • Using a list for seen: in becomes an O(n) scan.
  • Adding before checking, so every value finds itself.
  • Valid Sudoku: forgetting to skip ".", or skipping the box check.
  • Valid Sudoku: a box id like r // 3 + c // 3 that maps two boxes to one key.

Lookup by key (Two Sum, Longest Consecutive)

  • Two Sum: storing x before looking up target - x, which can return the same index twice.
  • Two Sum: sorting first and losing the original indices.
  • Longest Consecutive: counting a run from every element instead of only from starts (x - 1 missing), which is O(n²) on one long run.
  • Longest Consecutive: looping over nums with its duplicates instead of over the set.

Practice questions

Try each in your head first. Open the hint, then the answer, only after you commit to a guess. Each links to the problem's interactive page.

Practice 1 — Two Sum: nums = [2, 7, 11, 15], target = 9. At which index is the pair found, and what is in seen at that moment?

Hint: the pair is found when its second member arrives.

Answer: at i = 1 (x = 7, need = 2), with seen = {2: 0}. Returns [0, 1]. Step through it: Two Sum.

Practice 2 — Valid Sudoku: which sets does cell (4, 7) check, and what is its box id?

Hint: box id = (r // 3, c // 3).

Answer: rows[4], cols[7] and boxes[(1, 2)], the middle-right box. The digit is added to all three only if none of them holds it. See both solutions traced: Valid Sudoku.

Practice 3 — Longest Consecutive Sequence: in [100, 4, 200, 1, 3, 2], which numbers start a run?

Hint: x starts a run when x - 1 is not in the set.

Answer: 100, 200 and 1. Only 1 grows far: 1, 2, 3, 4, so the answer is 4. 2, 3 and 4 never start a count, which keeps the total work O(n). Walkthrough: Longest Consecutive Sequence.

Practice 4 — Contains Duplicate: why is if x in seen with seen = [] (a list) still O(n²)?

Hint: how does a list find a value?

Answer: a list has no hash table; in compares against every stored element. With all-distinct input, the i-th check scans i elements, about n²/2 in total: the brute force in disguise. Compare the approaches on Contains Duplicate.

Final takeaway

Name the key, check the memory, then record. Contains Duplicate looks up x, Two Sum looks up target - x, Valid Sudoku looks up the digit in three sets at once, Longest Consecutive Sequence looks up x - 1 and x + length. Same O(1) lookup each time, and the nested loop becomes a single pass.
