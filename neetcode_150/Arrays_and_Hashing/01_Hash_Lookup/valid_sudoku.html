36 · Valid Sudoku

Is any digit repeated inside a row, a column, or a 3×3 box?

The problem, in plain words

You get a half-filled Sudoku. You do not solve it. You only check the digits already written: inside every row, every column and every 3×3 box, no digit may appear twice. Empty cells (.) are ignored.

Example: LeetCode's second board puts an 8 in the top-left corner. Column 0 already has an 8 (row 3), and the top-left box already has an 8 (row 2, column 2). So the answer is false.
Watch out: "valid" is not "solvable". A board can pass every check and still have no solution.
the unit being checkedno repeatrepeated digit

Every row, column and box is a "unit". A board is valid when no unit holds the same digit twice.

A small board to step through

A full 9×9 trace would be 30 steps long. The notebook's code works for any n×n board with n = b², so both solutions below are traced on this 4×4 board with 2×2 boxes (it is the notebook's MINI_4x4 test). Rules are the same: digits 1–4, no repeats per row, column or box.

The catch: the 3 at row 2, column 2 and the 3 at row 3, column 3 share no row and no column. Only their box (bottom-right) sees the repeat. Answer: false.

Solution 1 — Brute force: every digit rescans its row, column and box

For each filled cell, walk its whole row, its whole column and its whole box, looking for the same digit somewhere else. No memory needed, but the same pairs get compared again and again.
current cellpeer being comparedalready passedtwin found

Speed & memory: each filled cell rescans about 3n peers, so an n×n board costs O(n³). On the real 9×9 board that is a fixed amount (at most 81 × 27 checks), O(1). No extra memory: O(1).

The brute force looks forward too, so it spots the repeat from the first 3 at (2, 2), before reaching (3, 3).

Solution 2 — The smart way: one pass, three memories

Keep a set of digits for every row, every column and every box. Visit each filled cell once. First ask its three sets "have you seen this digit?" Any yes means a repeat. If all say no, write the digit into all three sets and move on. The box of cell (r, c) is (r // b, c // b).

Speed & memory: each cell costs three instant lookups and three inserts, so an n×n board is O(n²) time and O(n²) memory; on the 9×9 board both are O(1). In the notebook's benchmark, growing the board 16× in cells made this ≈14–18× slower and the brute force ≈48–57× slower.

When you'd use this

See "no repeats within each row / column / group" or "each value at most once per unit"? Give every unit its own set, compute which units a cell belongs to, and check all of them before recording.
