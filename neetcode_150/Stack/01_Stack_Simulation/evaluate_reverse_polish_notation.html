150 · Evaluate Reverse Polish Notation

Work out a sum written with the operator after its two numbers.

The problem, in plain words

Normally we write 2 + 1. Reverse Polish Notation writes 2 1 +: the two numbers first, then what to do with them. You get the pieces (tokens) as a list of strings. Return the final number.

Example: ["4", "13", "5", "/", "+"] means 4 + (13 / 5) → 6.
Watch out: division drops the fraction toward zero. 13 / 5 is 2.6 → 2, and 7 / -2 is -3.5 → -3. Python's // would give -4, so the notebook uses int(a / b).

Each operator uses the two numbers just before it that have not been used yet.

Solution 1 — Brute force: collapse the first operator, start over

Scan from the left until you hit the first operator. No operator came before it, so the two tokens right before it are plain numbers. Replace those three tokens with their result, then scan again from the start. Stop when one token is left.

Speed & memory: every round rescans from the left and rebuilds the list, and there is one round per operator — O(n²) time. O(n) memory for the working copy.

Solution 2 — The smart way: a stack of numbers that are waiting

Read left to right. A number waits: put it on top of a pile (a stack). An operator takes the top two numbers off the pile: the first one off is the right number, the second is the left one. It puts the result back, because a later operator may need it. At the end, one number is left: the answer.

stack (top is on the right)

Speed & memory: one pass, each token costs one push or two pops and a push — O(n) time, O(n) memory for the stack.

When you'd use this

See "postfix / Reverse Polish", "evaluate an expression", or "each step uses the most recent values"? Push values while they wait, and let each operator pop what it needs and push its result back.
