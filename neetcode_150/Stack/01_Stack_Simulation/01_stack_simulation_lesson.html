Stack Simulation

Read the input once, left to right. Anything that cannot be finished yet goes on a stack and waits. When a token arrives that finishes something, the thing it needs is always the most recent one still waiting, which is exactly what the top of the stack holds. Pop it, check or combine it, and push any result back.

Core idea: the latest unfinished item is finished first Method 1: Valid Parentheses Method 2: Evaluate Reverse Polish Notation Interactive traces synced to code

Problems in this pattern: Valid Parentheses · Min Stack · Evaluate Reverse Polish Notation · pattern notes (README)

Canonical example

Valid Parentheses, s = "([]{})". Each closer must match the most recent unclosed opener.

Answer = True (every arc nests, nothing left open)

Why this pattern matters

Code editors and compilers

Matching brackets, tags and begin/end blocks is a stack: the innermost open block must close first.

Calculators and interpreters

Postfix expressions, and the bytecode of stack-based virtual machines, are evaluated by pushing values and letting each operator pop its inputs.

Undo with extra state

An undo history is a stack. Storing a summary (like the current minimum) with each entry lets you roll the summary back for free, as Min Stack does.

Instructor note: the three problems here look different (a string check, a class design, an expression evaluator), but each is one loop over the input with a list used as a stack. Learn to ask "what waits, and what resolves it?" and the code writes itself.

What is stack simulation?

Simple definition

A stack is a pile: append puts an item on top, pop takes the top item off, both O(1). Stack simulation means walking the input once and using that pile to hold items that are waiting: openers waiting for a closer, numbers waiting for an operator, values waiting to be popped.

The tell in a problem statement

"Valid / balanced parentheses", "matching pairs", "Reverse Polish / postfix", "evaluate the expression", "design a stack that also supports getMin in O(1)". In each, the most recent unfinished thing is the first to be finished.

Beginner shortcut: sort every token into one of two kinds. A token that waits gets pushed. A token that resolves pops the top and uses it. If you can name those two kinds, you have the algorithm.

Step-by-step thinking process

1

Name what waits

Openers (Valid Parentheses), numbers (RPN), (value, min) pairs (Min Stack).

2

Name what resolves

A closer, an operator, a pop() call. It always needs the most recent waiting item.

3

Push or pop per token

Wait → append. Resolve → guard against an empty stack, pop, check or combine, push a result if one is produced.

4

Read the answer from the stack

Empty at the end (parentheses), the single value left (RPN), or the top entry (Min Stack).

How the input becomes a stack

The input is a sequence (characters, tokens, or method calls). Nothing is pre-built: the stack is filled and emptied as the scan goes. What changes from problem to problem is what sits on the stack.

Input sequences

s = "([]{})" tokens = ["4", "13", "5", "/", "+"] calls = push(-2), push(0), push(-3)
→

What waits on the stack (bottom → top)

openers ['(', '['] after "([" numbers [4, 13, 5] after "4 13 5" pairs [(-2, -2), (0, -2), (-3, -3)]

Classify the token

Is it something that waits (opener, number, pushed value) or something that resolves (closer, operator, pop)?

Waiting token: push

Openers are pushed as characters, numbers as int(t), Min Stack values as (val, min(val, min below)).

Resolving token: pop the top

A closer compares the popped opener with match[c]; an operator pops two numbers and pushes the result.

End of input: inspect what is left

Leftover openers mean invalid; one number left is the RPN answer.

Critical point: a stack never changes below its top. That is why an item pushed earlier is still exactly as it was when its resolver arrives, and why Min Stack can store "the minimum of everything below me" once and trust it until that entry is popped.

Method 1: stack of openers (Valid Parentheses)

The template with openers as the waiting items, taken line for line from the notebook's valid_paren_stack. Each closer pops the most recent opener and must match it; at the end the stack must be empty. Traced on s = "([]{})".

def valid_paren_stack(s: str) -> bool: match = {")": "(", "]": "[", "}": "{"} # each closer mapped to the opener it needs stack = [] # holds the openers we've seen but not yet closed for c in s: # scan the string left to right if c in match: # c is a CLOSER # It's valid only if the most recent opener (top of stack) matches. if not stack or stack[-1] != match[c]: return False # nothing to close, or wrong type -> invalid stack.pop() # matched -> remove that opener else: # c is an OPENER stack.append(c) # remember it until its closer arrives return not stack # valid only if no opener was left unclosed

Key mental model

The stack is the list of "still open" brackets, innermost on top. A closer can only ever close the innermost one, so it only ever needs to look at the top.

Common mistake

Returning True after the loop without checking the stack. "((" never fails a match; it is invalid only because two openers are left over.

Why a stack

The repeated-removal brute force deletes (), [], {} pairs until nothing changes: O(n²). The stack finds each pair the moment its closer arrives, one pass, O(n).

Method 2: stack of operands (Evaluate Reverse Polish Notation)

Same loop, but a resolving token produces something. Numbers wait on the stack; each operator pops the right operand, then the left one, and pushes the result back for a later operator. Code from the notebook's eval_rpn_stack, traced on tokens = ["4", "13", "5", "/", "+"]. The notebook's OPS table maps each operator to a function:

OPS = {"+": operator.add, "-": operator.sub, "*": operator.mul, "/": lambda a, b: int(a / b)} # truncate toward zero, not floor
def eval_rpn_stack(tokens: List[str]) -> int: stack = [] # operands waiting for an operator for t in tokens: if t in OPS: # operator: resolve the two most recent operands b = stack.pop() # first pop = RIGHT operand a = stack.pop() # second pop = LEFT operand stack.append(OPS[t](a, b)) # the result waits like any other operand else: stack.append(int(t)) # number: push and wait return stack[0] # a valid expression leaves exactly one value

Key mental model

An operator's result is just another number waiting for a later operator. Pushing it back is what lets + at step 5 use the 2 that / produced at step 4.

Common mistake

Swapping the pops. The first pop is the right operand, so step 4 is 13 / 5, not 5 / 13. Also: // floors (7 // -2 == -4); the problem wants int(7 / -2) == -3.

Why a stack

The brute force finds the first operator, collapses it with its two operands, and rescans from the start: O(n²). The stack keeps the unused operands in exactly the order the next operator needs them: O(n).

Edge cases you should test

Case A: empty string

s = ""

Valid Parentheses = True

The loop never runs and the stack is empty, so return not stack gives True. Nothing is unbalanced.

Case B: a closer with nothing open

s = ")" or s = "]"

Valid Parentheses = False

The not stack half of the guard catches it before stack[-1] would raise IndexError on an empty list.

Case C: openers left at the end

s = "((" or s = "{[]}("

Valid Parentheses = False

No closer ever mismatches; the final return not stack is the only check that fails.

Case D: division with mixed signs

tokens = ["6", "-132", "/"] and ["7", "-2", "/"]

RPN = 0 and -3

int(6 / -132) is 0 and int(7 / -2) is -3. Floor division would give -1 and -4.

Case E: the minimum appears twice

push(0), push(1), push(0), getMin(), pop(), getMin()

Min Stack outputs = 0, 0

With (val, min) pairs the stack is [(0, 0), (1, 0), (0, 0)]; after the pop the top pair still says 0. In the two-stacks variant, pushing to the min-stack only on a strict < would break this case.

How to derive this in an interview

Reasoning path

Walk the input left to right. Some tokens cannot be finished yet: they have to wait.

When a token finishes something, it always needs the most recent waiting item. Most recent first is last in, first out: a stack.

Push waiting items; on a resolving token, guard against an empty stack, pop, check or combine, and push any result.

Decide what the leftover stack means: empty = valid, one value = answer. If a query must be O(1), store its answer with each entry.

What to say out loud

  • "The most recent unclosed bracket must close first, so I'll keep openers on a stack."
  • "In postfix, each operator applies to the two most recent unused values, so I push numbers and let each operator pop two and push the result."
  • "For getMin in O(1), I'll store the minimum so far with each entry, because nothing below the top ever changes."
  • "Each token is pushed or popped a constant number of times: O(n) time and O(n) space."

Common beginner coding mistakes

Valid Parentheses

  • Calling stack[-1] or stack.pop() on an empty stack when a closer comes first.
  • Returning True after the loop without checking that the stack is empty.
  • Only counting brackets: "([)]" has balanced counts but crossed pairs.

Min Stack

  • Keeping a single self.min: after the minimum is popped there is no way to recover the previous one.
  • Reading self.stack[-1] in push without handling the empty stack.
  • Two-stacks variant: pushing to the min-stack only on strict <, which breaks duplicate minimums.

Evaluate RPN

  • Swapping operands: computing b - a or b / a.
  • Using //, which floors negative results instead of truncating toward zero.
  • Detecting numbers with t.isdigit(), which is False for "-11". Test for the operator instead.

Practice questions

Try each in your head first. Open the hint, then the answer, only after you commit to a guess. Each links to the problem's interactive page.

Practice 1 — Min Stack: push(3), push(5), getMin(), push(2), push(2), getMin(), pop(), getMin()

Hint: write each entry as (value, min so far); the second 2 also stores min 2.

Answer: the three getMin calls return 3, 2, 2. The stack is [(3,3), (5,3), (2,2), (2,2)]; popping one (2,2) leaves another on top. Step through the design on Min Stack.

Practice 2 — Valid Parentheses: "{[]}(" and "]"

Hint: which of the two checks fails in each, the guard inside the loop or the final not stack?

Answer: both are False. "{[]}(" passes every match but leaves ( on the stack; "]" hits the not stack guard immediately. See Valid Parentheses.

Practice 3 — Evaluate RPN: ["2", "1", "+", "3", "*"]

Hint: push 2 and 1, then let + pop them; the result waits for *.

Answer: 9, which is (2 + 1) * 3. The stack goes [2], [2, 1], [3], [3, 3], [9]. Compare both approaches on Evaluate Reverse Polish Notation.

Practice 4 — Follow-up variant of Evaluate RPN: what does ["7", "-2", "/"] return, and what would a // b return?

Hint: 7 / -2 = -3.5. Which way does each rule round?

Answer: the problem wants -3 (truncate toward zero, int(7 / -2)); 7 // -2 floors to -4. The notebook's tests include this case. Walkthrough: Evaluate Reverse Polish Notation.

Final takeaway

Push what waits; when a token resolves something, pop the top and use it. Valid Parentheses pops an opener and checks it, Evaluate RPN pops two operands and pushes their result, and Min Stack stores the running minimum with every entry so a pop rolls it back. One pass, O(1) per token.
