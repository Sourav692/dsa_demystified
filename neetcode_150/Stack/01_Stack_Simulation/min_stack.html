155 · Min Stack

Build a stack that can also tell you its smallest value, instantly.

The problem, in plain words

A stack is a pile: you add to the top, remove from the top, and look at the top. Build one that can also answer "what is the smallest value in the pile right now?" — and every one of the four actions must be instant, no matter how tall the pile is.

Example: push -2, push 0, push -3. Smallest? -3. Pop. Top? 0. Smallest? -2.
The hard part: after -3 leaves, the smallest value has to go back to -2. One "smallest so far" number cannot remember that.

Solution 1 — Brute force: look through the whole pile on every getMin

Keep a plain list. Push, pop and top are the normal list moves. For getMin, walk every value in the pile and return the smallest (min(self.stack)).

outputs so far

Speed & memory: push, pop and top are instant, but every getMin walks the whole pile — O(n) per call, so n calls can cost O(n²). Memory O(n).

Solution 2 — The smart way: every entry remembers the smallest value at or below it

A pile only changes at the top, so what sits under an entry never changes while that entry is there. So when you push a value, also write down the smallest value of the pile at that moment: (val, min(val, min below)). getMin just reads the top entry. After a pop, the new top already holds the right answer.

outputs so far

Speed & memory: every action reads or changes only the top — O(1) each. Memory O(n): two numbers per entry instead of one.

When you'd use this

See "design a stack that also answers X instantly" or "retrieve the minimum in constant time"? Store the answer to X next to every entry. Because a stack never changes below its top, each stored answer stays true until its entry is popped.
