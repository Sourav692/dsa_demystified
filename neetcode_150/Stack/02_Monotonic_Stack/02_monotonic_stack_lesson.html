Monotonic Stack

Walk the input once and keep the elements that are still waiting for their answer on a stack of indices. Each new element pops every waiting element it beats, and that pop is the moment the popped element learns its answer: its next greater element, its next smaller element, a distance, a width. Because beaten elements are always removed, the values left on the stack stay sorted.

Core idea: a pop is an answer Method 1: decreasing stack (Daily Temperatures) Method 2: increasing stack + width (Largest Rectangle) Interactive traces synced to code

Problems in this pattern: Daily Temperatures · Car Fleet · Largest Rectangle in Histogram · pattern notes (README)

Canonical example

Daily Temperatures, [73, 74, 75, 71, 69, 72, 76, 73]. For each day, how many days until a warmer one?

Answer = [1, 1, 4, 2, 1, 1, 0, 0] (gray days never warm up)

Why this pattern matters

Price and weather series

"How many days until the price beats today's?" or "for how many days has the price been at most today's?" (a stock span) are next-greater questions over a time series, answered in one pass.

Skylines and visibility

Which buildings can see the sunset, who in a queue can see whom: a taller element hides every shorter one behind it, which is exactly what a pop records.

Largest areas

The biggest rectangle under a histogram, and the biggest all-ones rectangle in a binary matrix (one histogram per row), both reduce to "nearest shorter bar on each side".

Instructor note: the brute force for every problem here compares each element with everything after it, O(n²). The monotonic stack removes an element as soon as some later element answers it, so nothing is compared twice. Learn to ask "which elements are still waiting, and what ends their wait?"

What is a monotonic stack?

Simple definition

A stack (append / pop at the top, both O(1)) holding indices whose values stay sorted from bottom to top. Before pushing index i, you pop every index whose value would break that order. For "next greater" the values are decreasing (pop while the top is smaller than the new value); for "next smaller" they are increasing (pop while the top is larger).

The tell in a problem statement

"How many days until a warmer temperature", "next greater / next smaller element", "largest rectangle in a histogram", "the span where this element is the minimum", "cars cannot pass and form fleets". The answer for an element is decided by the first element after it that beats it.

Beginner shortcut: the stack is a waiting room. An element waits until something beats it. When something does, the waiting element leaves (pop) with its answer. Everything still in the room at the end never got beaten.

Step-by-step thinking process

1

Name the answer

For each element: the next greater (warmer day), the next smaller (the wall of a rectangle), or the fleet ahead (Car Fleet).

2

Pick the direction

Next greater → decreasing stack, pop while nums[top] < x. Next smaller → increasing stack, pop while nums[top] > x.

3

Write the answer at pop time

Store indices so the pop can compute a distance i - j or a width i - left - 1.

4

Handle the leftovers

Indices never popped keep a default (0 days) or are flushed by a sentinel (a height-0 bar after the end).

How the input becomes a monotonic stack

The input is a plain array. Nothing is pre-built: the stack is a running summary of "who is still waiting", and its values are always in order. The answer array is filled in by the pops, out of order.

Input array

temperatures = [73, 74, 75, 71, 69, 72, 76, 73] heights = [2, 1, 5, 6, 2, 3]
→

Stack of waiting indices (bottom → top)

after day 4: [2, 3, 4] temps 75 > 71 > 69 decreasing after bar 3: [1, 2, 3] heights 1 < 5 < 6 increasing

Read the next element

Compare it with the value of the index on top of the stack.

It beats the top: pop and answer

Pop the top index j and write its answer using the current index i. Repeat while it keeps beating the new top.

It does not beat the top: push

Push i. The stack is still sorted, because everything it would have broken the order with was just popped.

End of input: the leftovers

Daily Temperatures leaves them at 0; Largest Rectangle pushes a height-0 sentinel that pops them all.

Critical point: one step of the for loop can pop many indices, but each index is pushed exactly once and popped at most once in the whole run. That is why the nested while still totals O(n).

Method 1: decreasing stack (Daily Temperatures)

The template as is, taken line for line from the notebook's daily_temperatures_stack. Days waiting for a warmer day sit on the stack; a warmer day pops them and writes how long they waited. Traced on [73, 74, 75, 71, 69, 72, 76, 73].

def daily_temperatures_stack(temperatures: List[int]) -> List[int]: res = [0] * len(temperatures) stack = [] # indices of days still waiting; temps never rise bottom -> top for i, t in enumerate(temperatures): while stack and temperatures[stack[-1]] < t: # today is warmer than the day on top j = stack.pop() # day j's wait is over... res[j] = i - j # ...after i - j days (why we store INDICES) stack.append(i) # today waits for its own warmer day return res # days left on the stack keep 0

Key mental model

The stack is the list of days still waiting, coldest on top. A new day can only end the waits of days colder than itself, and those are all on top, so it pops from the top until it meets a day at least as warm.

Common mistake

Pushing temperatures instead of indices. The pop then knows the day was 69 but not which day it was, so i - j cannot be computed. NeetCode's Stack traps call this out by name.

Why a stack

The brute force scans right from every day, O(n²): about 4x slower per doubling of n in the notebook's benchmark. The stack touches each day twice (push, pop): O(n), about 2x per doubling.

Method 2: increasing stack + width (Largest Rectangle in Histogram)

Flip the comparison: now each bar needs its nearest shorter bar on both sides, so the stack keeps heights increasing and a shorter bar pops the taller ones. At pop time the current index is the right wall and the new top is the left wall. Code from the notebook's largest_rectangle_stack, traced on heights = [2, 1, 5, 6, 2, 3].

def largest_rectangle_stack(heights: List[int]) -> int: n = len(heights) stack = [] # bar indices, heights never decrease bottom -> top best = 0 for i in range(n + 1): h = heights[i] if i < n else 0 # sentinel 0 after the last bar flushes the stack while stack and heights[stack[-1]] > h: # top bar is taller: its rectangle can't pass i top = stack.pop() left = stack[-1] if stack else -1 # left wall: nearest bar on its left that is not taller best = max(best, heights[top] * (i - left - 1)) # width = bars strictly between the walls stack.append(i) return best

Key mental model

A bar stays on the stack while its rectangle can still grow to the right. The first shorter bar ends that growth (right wall); the bar below it on the stack is the nearest bar to its left that is not taller (left wall).

Common mistake

Width i - top instead of i - left - 1. At step 7, bar 4 (height 2) spans bars 2..5, width 4, because the taller bars 2 and 3 were popped earlier. Its own index would give width 2.

Why the sentinel

Bars that never meet a shorter bar would never be popped, so their areas would be lost: without it [1, 2, 3] returns 0 instead of 4. The height-0 bar at i = n is shorter than everything.

Edge cases you should test

Case A: temperatures that only fall

[90, 80, 70, 60]

Daily Temperatures = [0, 0, 0, 0]

Nothing is ever popped: every day stays on the stack and keeps its default 0. This is also the stack's largest size, n.

Case B: equal temperatures

[50, 50, 50, 51]

Daily Temperatures = [3, 2, 1, 0]

An equal day is not warmer, so the comparison is a strict <: the three 50s wait together and 51 pops all of them. Popping on <= would give [1, 1, 1, 0].

Case C: bars that only rise

[1, 2, 3, 4, 5]

Largest Rectangle = 9

No bar meets a shorter bar until the sentinel, which pops all five; height 3 across bars 2..4 gives 9. Without the sentinel the answer would wrongly be 0.

Case D: two cars arrive at the same moment

target = 10, position = [0, 5], speed = [2, 1]

Car Fleet = 1

Both need 5.0 hours. Catching up exactly at the target still forms one fleet, so the merge test is t <= stack[-1], not <.

Case E: a single element

temperatures = [55], heights = [1]

[0] and 1

Daily Temperatures pushes the only day and returns its default 0. Largest Rectangle pops the bar at the sentinel with left wall -1 and width 1.

How to derive this in an interview

Reasoning path

The brute force compares each element with everything after it: O(n²). Where is the waste?

Once a later, bigger element has answered an element, that element never matters again. Remove it.

The elements still unanswered are then always in sorted order, and the newest is on top: a stack. A new element pops the ones it beats and answers them.

Store indices, because the answer is a distance or a width. Each index is pushed and popped once: O(n).

What to say out loud

  • "Each day needs its next warmer day, so I'll keep a stack of days still waiting; their temperatures are decreasing."
  • "When today is warmer than the top, I pop it and its answer is i - j; that's why I store indices."
  • "For the histogram I need the nearest shorter bar on both sides, so the stack is increasing and the width is i - left - 1."
  • "Every index is pushed once and popped at most once, so it's O(n) time and O(n) space."

Common beginner coding mistakes

Daily Temperatures

  • Pushing temperatures instead of indices, so the distance is lost.
  • Popping on <=: an equal day is not warmer.
  • Using an if instead of a while: one warm day can end many waits.

Car Fleet

  • Not sorting, or sweeping from the back of the road instead of from the car closest to the target.
  • Merging only on <: a tie at the target is one fleet.
  • Integer division (target - p) // s, which rounds times down and merges cars that never meet.

Largest Rectangle

  • Width i - top instead of i - left - 1.
  • No sentinel or final flush, so bars that never meet a shorter bar are never measured.
  • Reading stack[-1] for the left wall without handling the empty stack (left wall = -1).

Final takeaway

Keep the unanswered indices on a stack; each new element pops the ones it beats and answers them. Daily Temperatures pops cooler days and writes i - j, Largest Rectangle pops taller bars and writes height × (i - left - 1), and Car Fleet, after sorting by position, keeps only the fleet times that increase. Each index is pushed once and popped once: one pass, O(n).
