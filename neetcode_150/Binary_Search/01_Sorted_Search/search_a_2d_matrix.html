74 · Search a 2D Matrix

A grid of sorted numbers. Is the target in it?

The problem, in plain words

You get a grid (rows and columns) of numbers. Each row goes from small to large, and each row starts with a number bigger than the last number of the row above. Answer yes or no: is the target somewhere in the grid? You must be as fast as one binary search over all the cells.

Read the grid like a book, left to right and top to bottom, and you get one long sorted list. That is the whole trick: binary search that list without ever building it.

The strip under the grid is the same 12 numbers read row by row. Index i in the strip lives at row i // 4, column i % 4.

Solution 1 — Brute force: check every cell

Go row by row, cell by cell, and compare each number with the target. It ignores all the sorting, so a missing target costs a look at every cell.

Speed & memory: all m·n cells in the worst case — O(m·n) time, O(1) memory. Measured: about 2× per doubling of the cell count.

Solution 2 — Better: walk a staircase from the top-right corner

Stand on the top-right cell. Everything left of it in its row is smaller; everything below it in its column is bigger. Too big? The whole column below is too big as well: step left. Too small? The whole row to the left is too small: step down. Each step throws away a whole row or column.

Speed & memory: at most one step per row plus one per column — O(m + n) time, O(1) memory. On a square grid that is about 1.4× per doubling of the cell count (the notebook measures about 1.5×).

Solution 3 — The smart way: one binary search over the "flat" list

Pretend the grid is the strip of 12 numbers. Binary search positions 0 to 11 with lo, hi, mid, exactly as in plain Binary Search. To read position mid, turn it into a cell: r, c = divmod(mid, 4) (row = mid // 4, column = mid % 4, where 4 is the number of columns).

Speed & memory: one binary search over m·n positions — O(log(m·n)) time, O(1) memory (the strip is never built). Measured: about 1× per doubling.

When you'd use this

See "each row is sorted" and "each row starts after the previous row ends"? The grid is one sorted list in disguise: binary search the positions and convert each one with divmod. If rows are sorted but do not chain, use the staircase instead.
