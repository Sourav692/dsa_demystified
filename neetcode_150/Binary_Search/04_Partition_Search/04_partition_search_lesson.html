Partition Search

Binary search for a cut, not for a value. To find the median of two sorted arrays, decide how many values the left half takes from the smaller array. The other array's share is then forced, and four boundary values tell you whether to move the cut left, move it right, or stop.

Core idea: search the cut i, derive j = half - i Method 1: partition search, O(log min(m, n)) Method 2: two-pointer walk to the middle, O(m + n) Interactive traces synced to code

Problem in this pattern: Median of Two Sorted Arrays · pattern notes (README) · look-alike: Sorted Search

Canonical example

Median of Two Sorted Arrays, the notebook's worked example: nums1 = [2, 4, 7, 10, 14, 17], nums2 = [8, 11, 16, 19]

Median = (max(8, 10) + min(11, 14)) / 2 = 10.5

Why this pattern matters

Percentiles across sorted shards

Two services each keep their response times sorted. The overall median, or any percentile, can be read without copying either list into a merged one.

The k-th smallest of two sorted lists

The same cut answers "which value is k-th overall": make the left side hold exactly k values and read its largest one.

Binary search beyond "find x"

The search space here is a set of cut positions, not stored values. Seeing that is what turns a linear merge into a logarithmic search.

Instructor note: this is the hardest problem in NeetCode's Binary Search list, but the loop is ordinary binary search. Everything difficult sits in two lines: j = half - i and the four-value check.

What is partition search?

Simple definition

A cut at position i splits a sorted array into A[:i] and A[i:]. Partition search binary searches the cut position in one array so that, together with a matching cut in the other array, the left pieces hold exactly the half smallest values. The median sits right at that boundary.

The tell in a problem statement

Two sorted arrays plus a question about their combined order: "median of the two arrays", "k-th smallest of the union". A required O(log (m + n)) rules out merging.

Beginner shortcut: you are not looking for a number, you are looking for how many numbers the left half borrows from the smaller array. Once that count i is fixed, the count from the other array is half - i, no choice left.

Step-by-step thinking process

1

Pick the smaller array

Swap so A has m ≤ n values. Then every cut i in 0..m gives a legal j.

2

Fix the left-half size

half = (m + n + 1) // 2. Guess i in the middle of lo..hi; set j = half - i.

3

Check four values

A[i-1] ≤ B[j] and B[j-1] ≤ A[i], with -inf / +inf for missing neighbours.

4

Move or answer

A[i-1] too big: hi = i - 1. B[j-1] too big: lo = i + 1. Both fine: read the median at the cut.

How the input becomes a cut position

The input is two sorted lists. The search never touches a merged list; it works on a single integer i (how many values of the smaller array go left). Everything else is derived from i.

Input arrays

nums1 = [2, 4, 7, 10, 14, 17] # m = 6 nums2 = [8, 11, 16, 19] # n = 4
→

Search space and derived values

A = [8, 11, 16, 19] B = nums1 # swapped half = (4 + 6 + 1) // 2 = 5 i in 0..4 j = 5 - i a_left = A[i-1] a_right = A[i] b_left = B[j-1] b_right = B[j]

Swap so A is the smaller array

nums2 has 4 values, nums1 has 6, so A = nums2, B = nums1.

Compute half = 5

10 values in total, so the left half holds 5. For an odd total the + 1 puts the middle value on the left.

The search space is i = 0..4

The left half can take none, some, or all 4 values of A. That is 5 possible cuts, not 10 values.

Each i fixes j and four boundary values

j = 5 - i is between 1 and 5, always inside B. A cut at an edge reads -inf or +inf for its missing neighbour.

Critical point: the check only needs the four values next to the cuts. Inside each array the order is already sorted, so A[:i] is below A[i:] for free; only the two cross-array pairs can break the split.

Method 1: partition search on the smaller array (Median of Two Sorted Arrays)

The template, line for line from the notebook's find_median_partition. Each pass of the loop is one guess for i; the four boundary values decide which half of lo..hi survives.

def find_median_partition(nums1: List[int], nums2: List[int]) -> float: A, B = nums1, nums2 if len(A) > len(B): A, B = B, A # search the smaller array m, n = len(A), len(B) half = (m + n + 1) // 2 # size of the left half lo, hi = 0, m # i = how many values the left half takes from A while lo <= hi: i = (lo + hi) // 2 # cut in A j = half - i # cut in B is forced a_left = A[i - 1] if i > 0 else float("-inf") a_right = A[i] if i < m else float("inf") b_left = B[j - 1] if j > 0 else float("-inf") b_right = B[j] if j < n else float("inf") if a_left <= b_right and b_left <= a_right: # valid cut if (m + n) % 2: return float(max(a_left, b_left)) return (max(a_left, b_left) + min(a_right, b_right)) / 2 elif a_left > b_right: hi = i - 1 # took too many from A: move the cut left else: lo = i + 1 # took too few from A: move the cut right raise ValueError("inputs must be sorted") # unreachable for sorted input

Key mental model

Picture two sliders, one per array, tied together so their positions always add up to half. Moving the A-slider right moves the B-slider left. You binary search the position where neither side holds a value that belongs on the other side.

Common mistake

Searching the larger array. In this example, cutting the 6-value array at i = 0..6 with j = 5 - i allows i = 6, j = -1: the 4-value array's [j - 1] becomes index -2, which Python silently reads from the end of the list.

Why sentinels

At step 6 the cut leaves nothing of A on the left. Treating the missing a_left as -inf makes a_left ≤ b_right automatically true, so the same two comparisons handle every edge cut.

Method 2: walk two pointers to the middle (the linear method it replaces)

The notebook's find_median_two_pointer: the merge step of merge sort, stopped at the middle and keeping only the last two values. It is the natural first answer, correct and O(1) space, but it still walks t // 2 + 1 steps, so it is O(m + n). Traced on the same input.

def find_median_two_pointer(nums1: List[int], nums2: List[int]) -> float: m, n = len(nums1), len(nums2) t = m + n i = j = 0 prev = cur = 0 for _ in range(t // 2 + 1): # walk to merged index t // 2, no further prev = cur # remember the value one position back if i < m and (j >= n or nums1[i] <= nums2[j]): cur = nums1[i]; i += 1 else: cur = nums2[j]; j += 1 if t % 2: return float(cur) return (prev + cur) / 2

Key mental model

Two people at the front of two sorted queues; the shorter one steps forward each time. After t // 2 + 1 steps, the last two people who stepped forward are the middle of the combined line.

Common mistake

Forgetting j >= n in the condition: once nums2 runs out, nums2[j] raises IndexError. The check must also take from nums1 whenever nums2 is used up.

Why it is not enough

It takes half of all values. In the notebook its time roughly doubled each time the input doubled, while the partition search stayed about flat (17 to 20 loop passes from 125,000 to 1,000,000 values per array).

Edge cases you should test

Case A: one array is empty

nums1 = [], nums2 = [2, 3]

Median = 2.5

A = [], so lo = hi = 0 and the only cut is i = 0, j = half = 1. Both A-values are sentinels (-inf, +inf), the check passes at once, and the answer is (2 + 3) / 2 from B alone.

Case B: odd total length

nums1 = [1, 3], nums2 = [2]

Median = 2.0

half = (1 + 2 + 1) // 2 = 2, so the left half holds the middle value. The valid cut is i = 1, j = 1 (left = 2 | 1), and the answer is max(a_left, b_left) = max(2, 1), returned as a float.

Case C: every value of A is smaller than every value of B

nums1 = [1, 2, 3], nums2 = [4, 5, 6, 7]

Median = 4.0

The valid cut takes all of A: i = m = 3, j = 1. a_right is the +inf sentinel. The search moves right on every guess, which is also why the notebook's benchmark uses this shape as the worst case.

Case D: equal values on both sides of the cut

nums1 = [1, 1, 1], nums2 = [1, 1]

Median = 1.0

The check uses ≤, not <, so equal values on both sides still count as a valid split. With strict < no cut would ever pass.

How to derive this in an interview

Reasoning path

Merging works but is O(m + n); the required O(log (m + n)) means binary search.

There is no single sorted array to search, so ask: what number, if I knew it, would give me the answer? How many values the left half takes from A.

That count i fixes j = half - i. The split is right when A[i-1] ≤ B[j] and B[j-1] ≤ A[i].

If A[i-1] is too big, fewer from A; otherwise more. That one-way answer makes i binary-searchable. Search the smaller array, add sentinels, read the median at the cut.

What to say out loud

  • "Merging is linear, but the target is logarithmic, so I won't build the merged array."
  • "I'll binary search how many elements the left half takes from the smaller array; the rest come from the other one."
  • "A cut is valid when both cross pairs are in order; missing neighbours are minus and plus infinity."
  • "I search the smaller array so j stays in range: O(log min(m, n)) time and O(1) space."

Common beginner coding mistakes

Partition search

  • Searching the larger array, so j leaves 0..n.
  • Setting hi = m - 1 instead of m: the cut "take all of A" becomes impossible (Case C).
  • Mixing half = (m + n) // 2 with the odd answer max(left): one convention or the other.
  • Averaging with //: (10 + 11) // 2 is 10, not 10.5.

Merge and two-pointer walk

  • Not handling one array running out (j >= n), which raises IndexError.
  • Walking t // 2 steps instead of t // 2 + 1, so cur stops one short of the middle.
  • Forgetting to update prev before overwriting cur, which breaks even totals.
  • Calling it optimal: it is O(m + n), the problem asks for O(log (m + n)).

Practice questions

This pattern has a single NeetCode problem, so questions 2 to 5 are follow-up variants of it. Try each before opening the hint, then the answer. The interactive page is Median of Two Sorted Arrays.

Practice 1 — Median of Two Sorted Arrays: nums1 = [1, 2], nums2 = [3, 4]

Hint: both arrays have 2 values, so no swap; half = 2. Start with i = 1.

Answer: 2.5. i = 1, j = 1: a_left = 1 ≤ b_right = 4, but b_left = 3 > a_right = 2, so lo = 2. i = 2, j = 0: a_left = 2 ≤ b_right = 3 and b_left = -inf ≤ a_right = +inf, valid: (2 + 3) / 2. Compare with the walkthrough on the problem page.

Practice 2 — Variant: odd total, nums1 = [1, 3], nums2 = [2]. Which cut is valid, and which value is returned?

Hint: A = [2] (smaller), B = [1, 3], half = 2; the left half gets the extra value.

Answer: i = 0, j = 2 fails (b_left = 3 > a_right = 2, so lo = 1); i = 1, j = 1 is valid. Odd total, so return max(a_left, b_left) = max(2, 1) = 2.0. See Median of Two Sorted Arrays.

Practice 3 — Variant: one array empty, nums1 = [], nums2 = [2, 3]. Does the template need a special case?

Hint: what is lo..hi when m = 0, and what do the sentinels give?

Answer: no special case. lo = hi = 0, so the only guess is i = 0, j = half = 1; a_left = -inf, a_right = +inf pass every check, and the answer comes from B: (2 + 3) / 2 = 2.5. The notebook tests this case.

Practice 4 — Variant: the k-th smallest value of two sorted arrays. What changes in the template?

Hint: the left side should hold exactly k values instead of half. Which i keep j = k - i inside 0..n?

Answer: set j = k - i, search i in max(0, k - n) .. min(k, m) so j stays legal, and return max(a_left, b_left) once the cut is valid. On this lesson's example, k = 5 gives 10 and k = 6 gives 11, the two middle values. (Not a notebook problem; checked against sorting on random inputs while writing this lesson.)

Practice 5 — Variant: why must the search run on the smaller array?

Hint: in the canonical example, try searching B (6 values) with half = 5.

Answer: cutting the 6-value array allows i = 6, which gives j = -1, outside the 4-value array; Python would read index -2 silently instead of failing. With m ≤ n, j = half - i is always in 0..n. As a bonus the search is O(log min(m, n)).

Final takeaway

Search the cut, not the value. Choose how many values the left half takes from the smaller array, let the other array fill the rest, and check the four values that touch the cuts. If the left side of A is too big, move left; if the left side of B is too big, move right; otherwise the median is on the boundary. Same binary search loop, a new search space.
