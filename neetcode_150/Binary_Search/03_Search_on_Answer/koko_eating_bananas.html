875 · Koko Eating Bananas

How slowly can Koko eat and still finish before the guards come back?

The problem, in plain words

Koko has a few piles of bananas and h hours. She picks one speed k (bananas per hour). Each hour she eats up to k bananas from one pile; if the pile runs out early, she rests for the rest of that hour. Find the slowest speed that still finishes every pile in time.

Example: piles = [3, 6, 7, 11], h = 8 → 4. At speed 4 the piles take 1 + 2 + 2 + 3 = 8 hours. At speed 3 they take 10 hours: too slow.
Hours for one pile = bananas ÷ speed, rounded up (a half-eaten hour still costs the whole hour). In code: (p + k - 1) // k.

Solution 1 — Brute force: try speed 1, 2, 3, … until one fits

Start at the slowest speed and go up one at a time. For each speed, add up the hours every pile needs. The first speed whose total is at most h is the answer, because every slower speed already failed.

Speed & memory: one full pass over the piles for every speed up to the biggest pile — O(n·M) time (M = biggest pile, up to 109), O(1) extra memory. Measured about 4x slower per doubling when piles and speeds grow together.

Solution 2 — The smart way: binary search the speed

Speeds line up as too slow, too slow, …, fits, fits, fits: once a speed works, every faster one works too. So guess the middle speed. If it fits, the answer is that speed or slower: keep the left half including it (hi = mid). If it is too slow, the answer is faster: lo = mid + 1. Each check throws away half the speeds.

Speed & memory: about log2(biggest pile) checks (around 30 for 109), each one pass over the piles — O(n log M) time, O(1) extra memory. Measured about 2x per doubling, against 4x for the brute force.

When you'd use this

See "the minimum speed / capacity / days such that you finish within a limit", a huge range of possible answers (up to 109), and a quick way to check one guess? Binary search the answer itself, using the check to pick a half.
