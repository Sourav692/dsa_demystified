543 · Diameter of Binary Tree

The longest walk between any two nodes.

The problem, in plain words

Find the longest path between any two nodes, counting edges (the lines), not nodes. The path does not have to go through the root.

Think of the tree as a set of hiking trails: what is the longest hike you can take without walking any trail twice? Every such hike has one highest point where it turns around.
looking atbeing measureddone / on the answer path

Try it: walk the longest path in [1, 2, 3, 4, 5]

Way 1 — Brute force: re-measure heights at every node

The longest path that turns at a node uses height(left) + height(right) edges. So visit every node, measure both sides from scratch with a separate height() walk, and keep the biggest sum. Lower nodes get measured again by every ancestor.

Speed: heights re-measured from every ancestor — O(n²) on a one-sided chain, O(n log n) on a balanced tree. Memory: O(h) for the recursion.

Way 2 — The smart way: return height, update a global best

One post-order DFS. Each call gets left and right heights from its children. It records left + right in a shared best (the path turning here), and returns 1 + max(left, right) — a parent can only extend one arm.

Speed: each node visited once — O(n) time. Memory: O(h) for the recursion.

When you'd use this

See "longest path between any two nodes" or "may or may not pass through the root"? Return the height from a post-order DFS and keep the two-armed answer in a global variable.
