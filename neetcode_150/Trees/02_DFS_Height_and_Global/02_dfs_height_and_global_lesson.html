DFS Height and Global

A post-order DFS that returns one thing to its parent (a height, or a best downward gain) while updating another: a global best answer, or a -1 sentinel that means "already failed". This page teaches the pattern on Balanced Binary Tree, then shows the global-variable version on Diameter of Binary Tree.

Core idea: return one arm, record two arms Method 1: height or -1 Method 2: height + global best Code synced with steps

Answer = False (node 2: left height 2, right height 0)

Why this pattern matters

Self-balancing trees

AVL trees keep every node's left and right heights within 1 of each other. Checking that rule is exactly Balanced Binary Tree.

Longest route in a hierarchy

In any tree-shaped network (an org chart, a file tree, a cable network without loops), the longest route between two endpoints is the tree's diameter.

Pattern reuse

The same skeleton solves Balanced Binary Tree, Diameter of Binary Tree, and Binary Tree Maximum Path Sum.

Instructor note: the hard part is not the DFS. It is noticing that what the parent needs (one arm) is different from the answer (two arms, or a yes/no). Once you see that split, the code writes itself.

What is the DFS Height and Global pattern?

Simple definition

One recursive function visits the children first (post-order). It returns a single number upward, and as a side effect it updates an answer that lives outside the recursion.

The tell in a problem statement

"At every node, compare left and right", "path between any two nodes", "may or may not pass through the root". Or: your first idea calls height() inside another recursion over every node.

Beginner shortcut: at each node, record the value that uses both children (left + right) and return the value that uses one (1 + max(left, right)). If the answer is a yes/no instead, return -1 to mean "no".

Step-by-step thinking process

1

Base case

What does an empty subtree hand back? For heights it is 0.

2

Children first

Call the function on the left and right child. Post-order, so each node sees finished child values.

3

Side effect

Use both child values: update best with left + right, or return -1 if the node breaks a rule.

4

Return one arm

Hand the parent only what it can extend: 1 + max(left, right).

How the input becomes a tree

LeetCode gives the tree as a level-order list, where null means "no child here". The notebook's build_tree turns it into linked TreeNode objects using a queue of parents waiting for children.

→

Linked nodes

Read 1

It becomes the root and joins the queue of parents.

Read 2, 3

Parent 1 takes 2 as left child and 3 as right child. Both join the queue.

Read 4, None

Parent 2 takes 4 on the left; its right stays empty.

Read None, None

Parent 3 gets no children: it is a leaf.

Read 5

Parent 4 takes 5 on the left. The list is used up.

Critical point: the DFS never sees the list. It only sees node.left and node.right, and an empty child is None, which the base case turns into height 0.

Method 1: Height or -1 sentinel (Balanced Binary Tree)

The function returns the subtree's height when it is balanced, and -1 when anything inside it is not. A node that receives -1 passes it straight up. This is is_balanced_optimal from the notebook, line for line.

def is_balanced_optimal(root: Optional[TreeNode]) -> bool: def check(node): # height of node's subtree, or -1 if it is unbalanced if not node: return 0 # empty subtree: height 0, trivially balanced left = check(node.left) if left == -1: return -1 # left side already failed -> pass the failure straight up right = check(node.right) if right == -1: return -1 if abs(left - right) > 1: return -1 # this node breaks the rule return 1 + max(left, right) # healthy: hand the parent our real height return check(root) != -1

Key mental model

One return value, two meanings: a height (0 or more) when healthy, -1 when already failed. Heights are never negative, so the signals cannot collide.

Common mistake

Forgetting if left == -1: return -1. Then a parent computes 1 + max(-1, 0) and treats the failure as a real height.

Why post-order matters

The brute force asks for heights top-down, so lower heights are re-measured by every ancestor (O(n²) upper bound). Bottom-up, each height is computed once: O(n).

Method 2: Height plus a global best (Diameter of Binary Tree)

Same skeleton, but now the answer is a number that uses both arms. The function still returns a height; the two-armed value left + right is written into best, a variable outside the recursion. This is diameter_optimal from the notebook.

def diameter_optimal(root: Optional[TreeNode]) -> int: best = 0 # longest path (in edges) seen anywhere so far def depth(node): # returns the height of node's subtree nonlocal best if not node: return 0 left = depth(node.left) right = depth(node.right) best = max(best, left + right) # side effect: the path that bends at this node return 1 + max(left, right) # the parent can only use ONE arm depth(root) return best

Key mental model

Every path has one highest node where it bends. Checking "the path bending here" (left + right) at every node covers every path, including ones that skip the root.

Common mistake

Returning left + right to the parent. A parent's path can only continue down one side of a child.

Why the global matters

The root's return value here is 3 because it is the tree's height. It only matches the diameter by coincidence; the answer always comes from best.

Edge cases you should test

Case A: empty tree

root = []

Balanced = True · Diameter = 0

The base case returns 0 at once. Make sure your wrapper does not crash on None.

Case B: one-sided chain

root = [1, null, 2, null, 3]

Balanced = False · Diameter = 2

Node 1 has left height 0 and right height 2. A chain is also the worst case for the brute force and the deepest recursion (h = n).

Case C: longest path skips the root

root = [1, 2, null, 3, 4, 5, null, null, 6]

Diameter = 4 (5 → 3 → 2 → 4 → 6)

Only checking left + right at the root gives 3. This is why the update runs at every node.

Case D: all-negative values (Max Path Sum)

root = [-3]

Max path sum = -3

Seed best with -inf, not 0, or you would report a path sum of 0 that no path has.

How to derive this in an interview

Reasoning path

The rule (or the path) at a node depends on the left and right subtree heights.

Calling height() at every node repeats work: O(n²) in the worst case.

Post-order DFS gives each node its children's heights for free, once.

The answer is not the height, so store it in a global (or encode failure as -1) and return the height.

What to say out loud

  • "Each node needs its children's heights, so I'll compute them bottom-up in one DFS."
  • "The function returns the height, the one arm a parent can extend."
  • "As a side effect I update a global best with left + right, the path bending here." (Or: "I return -1 to mean unbalanced and short-circuit.")
  • "Every node is visited once: O(n) time, O(h) stack space."

Common beginner coding mistakes

Method 1 (sentinel) mistakes

  • Checking balance only at the root; every node must pass.
  • Not returning -1 as soon as a child returns -1.
  • Returning True/False from the helper and losing the height the parent needs.
  • Calling height() inside the recursion (that is the brute force again).

Method 2 (global) mistakes

  • Returning left + right instead of 1 + max(left, right).
  • Returning the root's height as the answer instead of best.
  • Forgetting nonlocal best, so Python treats best as a new local variable.
  • Counting nodes instead of edges in the diameter, or seeding best = 0 for Max Path Sum.

Final takeaway

When a node's answer needs both children but its parent can only use one, split the two jobs: return the one-arm value (a height or a gain) and record the two-arm value in a global, or fold a yes/no into a -1 sentinel. One post-order pass, O(n).
