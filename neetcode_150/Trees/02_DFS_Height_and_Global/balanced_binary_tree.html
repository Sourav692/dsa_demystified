110 · Balanced Binary Tree

Is every node's left side about as tall as its right side?

The problem, in plain words

A tree is balanced when, at every node, the left side and the right side differ in height by at most 1. Return True or False.

Height = how many nodes you pass going straight down from a node to its deepest leaf (an empty side has height 0).

Think of a mobile hanging from the ceiling: it only hangs straight if every joint is balanced, not just the top one.
looking atbeing measuredpasses / answerfails

Try it: check every node of [3, 9, 20, null, null, 15, 7]

Way 1 — Brute force: re-measure heights at every node

Go to each node. Measure the height of its left side and right side from scratch with a separate height() walk. If they differ by more than 1, stop with False. Otherwise check the children the same way. Lower nodes get measured again by every ancestor — that is the wasted work.

Speed: heights get re-measured from every ancestor — O(n log n) on a balanced tree, O(n²) as an upper bound. Memory: O(h) for the recursion.

Way 2 — The smart way: one bottom-up DFS that returns height or -1

Ask the children first (post-order). Each call returns its height if its subtree is fine, or -1 if something below is already unbalanced. A node that sees -1 from a child just passes -1 up. Every height is measured once.

Speed: each node visited at most once — O(n) time. Memory: O(h) for the recursion.

When you'd use this

See "at every node, compare the left and right subtrees" or "height-balanced"? Return the height from a post-order DFS and use an impossible value like -1 to carry "already failed" up to the root.
