199 · Binary Tree Right Side View

Stand on the right of the tree. Which nodes can you see?

The problem, in plain words

Picture the tree drawn on a wall, and you stand to its right. On every level (row) you see only the node closest to you: the rightmost one. List those nodes from top to bottom.

Example: [1,2,3,null,5,null,4] → [1, 3, 4]. On the bottom row, 5 is hidden behind 4.
Watch out: the answer is not just "keep walking right". If the right side is shorter, a node from the left side shows through: [1,2,3,4,null,null,null,5] → [1, 3, 4, 5].

Each row shows one answer. The arrows on the right are your line of sight.

Solution 1 — Brute force: rescan the tree for every row

For row 0, then row 1, then row 2 … start again at the root and walk the tree left to right, stopping at that row. The last node you meet on the row is the rightmost one. When a row is empty, you are done.

answer so far

Speed & memory: every pass walks the whole top of the tree again, so a tall, thin tree gets slow fast — O(n·h) time (O(n²) on a chain), O(h) extra memory.

Solution 2 — Dive deep, right side first

Explore the tree depth-first, always trying the right child before the left. Then the first node you ever reach on a new row must be that row's rightmost node. One check does it: "is this row still missing from the answer?" (depth == len(res)).

answer so far

Speed & memory: every node is visited once — O(n) time; the stack holds about one path — O(h) memory.

Solution 3 — The smart way: BFS, keep the last node of each level

Use a queue (a waiting line). At the start of a level, the queue holds exactly that level, so pop exactly len(q) nodes, left to right, pushing their children to the back. The last node popped is the rightmost on the level — record it.

queue (front is left)

answer so far

Speed & memory: every node joins and leaves the queue once — O(n) time; the queue holds about one level — O(w) memory (w = widest level).

When you'd use this

See "visible from the side", "rightmost / leftmost per level" or "one answer per row"? Run level-order BFS and keep just the node you need from each level.
