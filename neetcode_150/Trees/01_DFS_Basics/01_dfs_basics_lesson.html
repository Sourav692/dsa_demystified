DFS Basics: one question, asked at every node

Most easy and medium tree problems are the same recursive function in different clothes: handle the empty node, do a little work at this node, ask both children the same question, and combine their answers on the way back up. This lesson traces that skeleton on Invert Binary Tree, then on Count Good Nodes, where a value is also passed down the tree.

Core idea: base case, work, recurse, combine Method 1: Invert Binary Tree Method 2: state passed down (Count Good Nodes) Interactive traces synced to code

Canonical example: Invert Binary Tree

root = [4,2,7,1,3,6,9]: swap left and right at every node.

Answer = [4,7,2,9,6,3,1]

Why this pattern matters

Folder sizes

A folder's size is its own files plus the size of each subfolder. That is "combine the children's answers", the same shape as Maximum Depth.

Comparing two structures

Checking that two nested documents or two trees are identical walks both in lockstep, exactly like Same Tree.

Pattern reuse

The same skeleton solves all five problems here and is the starting point for Diameter, Validate BST, and Max Path Sum.

Instructor note: do not memorise five solutions. Memorise one function shape and learn to fill in its four blanks: the base value, the work at a node, what to pass down, and how to combine.

What is DFS on a binary tree?

Simple definition

Depth-first search goes as deep as it can down one branch, then backs up and tries the next. On a tree you write it as a recursive function: a function that calls itself on node.left and node.right. A tree is a node plus two smaller trees, so the same function works at every level.

What you are computing

One answer per subtree, built bottom-up: a mirrored subtree (Invert), a height (Max Depth), a yes/no (Same Tree, Subtree), or a count (Count Good Nodes). Sometimes the children also need a fact from above, such as the largest value on the path so far, which travels down as an argument.

The tell: the input is a root, and the answer for a node can be built from the same answer for its children. Words like depth, height, mirror, identical, subtree, or "on the path from the root" point here.

Beginner shortcut: trust the recursive call. Assume dfs(node.left) already returns the right answer for the left subtree, and only ask: what do I do with the two answers at this node?

Step-by-step thinking process

1

Base case

What does an empty subtree return? None for Invert, 0 for depth or counts, True when two empties are compared.

2

Work at this node

The one small job for the current node: swap its children, compare its value, or decide if it is good.

3

Recurse, passing state down

Call the same function on both children. If they need a fact about the ancestors, such as the max so far, pass it as an argument.

4

Combine and return

Build this node's answer from the two child answers: return the node, 1 + max(l, r), l and r, or good + l + r.

How the input becomes a tree

LeetCode gives the tree as a level-order list where null marks a missing child. The notebooks' build_tree turns it into linked TreeNode objects using a queue of parents still waiting for children.

Input list

root = [4, 2, 7, 1, 3, 6, 9]
→

Linked nodes

4.left = 2 4.right = 7 2.left = 1 2.right = 3 7.left = 6 7.right = 9 1, 3, 6, 9: no children

Read 4

It becomes the root and joins the queue of parents.

Pop 4, read 2 and 7

They become 4's left and right children and join the queue.

Pop 2, read 1 and 3

They become 2's children.

Pop 7, read 6 and 9

They become 7's children. The list is used up.

Critical point: once the tree is linked, the recursion itself is the second structure. Each open call is a frame on the call stack, and the open frames are always one root-to-node path. That is why the space cost is O(h), the height of the tree.

Method 1: the template on Invert Binary Tree

The work at each node is one swap. Python evaluates the right-hand side first, so invert_rec(root.right) runs, then invert_rec(root.left), and only then are the two results assigned in swapped positions. This is the notebook's Approach 1, line for line.

def invert_rec(root: Optional[TreeNode]) -> Optional[TreeNode]: if not root: return None # nothing to flip # Swap the two children (each recursively inverted first). root.left, root.right = invert_rec(root.right), invert_rec(root.left) return root

Key mental model

A node is finished only after both of its children are finished. The blue wave in the trace moves bottom-up: leaves return first, the root returns last.

Common mistake

Writing root.left = invert_rec(root.right) and then root.right = invert_rec(root.left) on two lines. The second line reads the already-replaced left child. One tuple assignment avoids that.

Why the call stack matters

The green nodes are calls waiting for a child to return. They always form one path from the root, so memory is O(h), not O(n).

Method 2: passing state down (Count Good Nodes)

A node is good if no node above it on its root path is bigger. The children need one fact from above, the largest value so far, so it rides along as the argument max_so_far. Counts come back up and are added. This is the notebook's optimal approach, line for line, on root = [3,1,4,3,null,1,5].

def good_nodes_dfs(root: Optional[TreeNode]) -> int: def dfs(node, max_so_far): if not node: return 0 # base case: empty adds nothing good = 1 if node.val >= max_so_far else 0 # nothing above is bigger -> good new_max = max(max_so_far, node.val) # state handed DOWN to the children # Combine: this node's 0/1 plus the counts coming UP from both subtrees. return good + dfs(node.left, new_max) + dfs(node.right, new_max) return dfs(root, root.val) if root else 0 # root is good: compare it to itself

Key mental model

State about ancestors flows down as an argument. Answers about subtrees flow up as return values. One function does both.

Common mistake

Using > instead of >=. The lower-left 3 ties the 3 above it and still counts. Starting max_so_far at 0 breaks trees with negative values.

Why one number is enough

The brute force keeps the whole path and re-scans it at every node: O(n·h). Only the path's maximum decides the answer, so carrying that one number makes it O(n).

Edge cases you should test

Case A: empty tree

root = [] (so root is None)

Max Depth = 0 · Same Tree([], []) = True · Invert returns []

The base case is the whole answer. Every notebook tests this; it is why the empty check comes first.

Case B: a single node

root = [1]

Max Depth = 1 · Good nodes = 1

Both children hit the base case immediately. The root is always good because dfs(root, root.val) compares it with itself.

Case C: a chain (skewed tree)

1 → 2 → 3 → … → n, each node only a right child

Height h = n · Good nodes = n · n nested calls

Here O(h) space becomes O(n), and the brute force becomes O(n²). The Count Good Nodes benchmark uses this chain and raises Python's recursion limit to survive it.

Case D: equal values

root = [3,3,null,4,2]

Good nodes = 3

The second 3 ties its parent and is good; the 4 is good; only the 2 under a 3 is not.

How to derive this in an interview

Reasoning path

The input is a tree, and the answer covers every node.

Can a node's answer be built from its children's answers? Then recurse.

Does a node need to know something about its ancestors? Pass it down as an argument.

Does the answer pass through a node using both children (a diameter, a path sum)? Then a plain return is not enough; that is the next pattern, height plus a global.

Each node does O(1) work once: O(n) time, O(h) stack.

What to say out loud

  • "The answer for a node depends only on its children's answers, so I'll write one recursive DFS."
  • "Base case: an empty node returns 0 (or None, or True)."
  • "Children need the max on the path so far, so I pass it down as an argument and return counts up."
  • "Every node is visited once: O(n) time, O(h) space for the call stack, which is O(n) on a skewed tree."

Common beginner coding mistakes

Method 1 (combine up) mistakes

  • Reading node.val before checking if not node.
  • Swapping on two lines, so the second line sees the already-replaced child.
  • Forgetting to return root after inverting.
  • In Same Tree, checking values before the both-empty and one-empty cases.
  • Confusing depth in nodes with depth in edges.

Method 2 (state down) mistakes

  • > instead of >=: equal values are good.
  • Starting max_so_far at 0; negative values then break. Start at root.val.
  • Updating the max before checking the node.
  • Ignoring the recursion limit on very deep trees.

Practice questions

Each one is this pattern with a different fill-in. Name the base case and the combine step before you open the answer.

Practice 1 (Easy) — Maximum Depth of Binary Tree: how tall is [3,9,20,null,null,15,7]?

Hint: no state goes down. An empty tree has depth 0.

Answer: 3. Combine is 1 + max(depth(left), depth(right)). Open the interactive walkthrough.

Practice 2 (Easy) — Same Tree: are [1,2] and [1,null,2] the same?

Hint: walk both trees at once. Handle "both empty" and "one empty" before comparing values.

Answer: False. The values match but the 2 hangs on different sides. Combine is same(l1, l2) and same(r1, r2). Open the interactive walkthrough.

Practice 3 (Easy) — Subtree of Another Tree: is [4,1,2] inside [3,4,5,1,2]?

Hint: run Same Tree at every node of the big tree.

Answer: True. The subtree rooted at 4 matches. Combine is is_subtree(left) or is_subtree(right), O(m·n); serializing both trees with markers gets O(m+n). Open the interactive walkthrough.

Practice 4 (Medium) — Count Good Nodes: how many good nodes in [3,3,null,4,2]?

Hint: pass the max so far down; remember ties count.

Answer: 3. The root 3, the second 3, and the 4 are good; the 2 is not. Open the interactive walkthrough.

Practice 5 — Invert Binary Tree: what does [2,1,3] become?

Answer: [2,3,1]. Open the interactive walkthrough.

Final takeaway

Every problem in this pattern is one recursive function with four blanks: what an empty node returns, what work happens at this node, what is passed down, and how the two child answers combine. Fill those in, and Invert, Max Depth, Same Tree, Subtree, and Count Good Nodes all fall out in a few lines, at O(n) time and O(h) stack.
