Opposite Ends

Put one pointer at each end of an array or string and walk them toward each other. Every step looks at the two ends together and moves exactly one pointer inward, chosen by a rule that proves the element you leave behind cannot be part of a better answer. The pointers meet after at most n - 1 steps, so a problem that looks like "check every pair" (O(n²)) becomes one linear pass with O(1) extra memory.

Core idea: each step finishes one end Method 1: Valid Palindrome Method 2: Two Sum II (sorted) Interactive traces synced to code

Problems in this pattern: Valid Palindrome · Two Sum II · 3Sum · Container With Most Water · Trapping Rain Water · pattern notes (README)

Canonical example

Valid Palindrome, s = "Taco cat": ignoring case and anything that is not a letter or digit, does it read the same both ways?

Answer = True (T/t, a/a, c/c match; the space is skipped)

Why this pattern matters

Matching against a mirror

Palindromes, reversing a string in place, checking that a sequence is symmetric: position k from the left is always compared with position k from the right.

Pairs in sorted data

"Two prices that fit the budget", "two readings that add to a target", 3Sum and 4Sum: sorted order tells you which end is hopeless, with no extra memory.

Bounded by the weaker side

Container With Most Water and Trapping Rain Water: the shorter wall sets the limit, so the shorter side is the one you can finish and move past.

Instructor note: the whole skill is one sentence you must be able to justify out loud: "this end can't be part of any better answer, so I drop it". If you can't say why, the pointer move is a guess.

What is the opposite-ends two-pointer pattern?

Simple definition

Two integer indices, lo at the start and hi at the end. While lo < hi, look at the two ends together, then move one of them inward (or both, when both ends are finished, as in a palindrome match). The range [lo, hi] shrinks every step; everything outside it is settled for good.

The tell in a problem statement

Sorted input plus a pair ("two numbers that sum to target", "triplets that sum to zero"); palindrome or "reads the same backwards"; a pair of positions scored by the shorter side ("most water", "water trapped"); or an O(1) extra space rule on a problem whose easy fix is a hash map.

Beginner shortcut: picture all pairs (lo, hi) as a triangle. One comparison of the two ends rules out a whole row of that triangle (every pair that uses the dropped element), which is why n - 1 steps are enough instead of n(n-1)/2.

Step-by-step thinking process

1

Spot the shape

Sorted input with a pair, a mirror comparison, or "limited by the shorter side". The brute force is "every pair".

2

Start at the extremes

lo, hi = 0, len(a) - 1. The widest range, the smallest and largest values, the outermost characters.

3

Look at both ends

Compare, sum, or score a[lo] with a[hi]. If that is the answer, return it.

4

Drop the finished end

Prove which end cannot be in a better answer and move only that pointer. Loop while lo < hi.

How the input becomes a shrinking range [lo, hi]

The algorithm never builds a new structure. Its whole state is two integers. The input is read through them: the characters or values between lo and hi are still open, everything outside is settled. Here is that view for the canonical string.

Input string

s = "Taco cat" # len 8, indexes 0..7
→

Ranges the loop visits

[0, 7] "Taco cat" compare T / t [1, 6] "aco ca" compare a / a [2, 5] "co c" compare c / c [3, 4] "o " skip ' ', then j = 3 [4, 2] empty lo >= hi: stop

Start with the full range

i = 0, j = 7. Nothing is settled yet.

Each match settles two characters

When s[i] and s[j] agree (ignoring case), both are done, so both pointers step in: the range loses two characters.

Each skip settles one character

A space or punctuation mark does not count, so that pointer moves past it on its own.

The range empties

When i >= j every mirror pair has been checked. The middle character of an odd-length string has no partner and needs no check.

Critical point: for sorted pair problems the same picture holds with values instead of characters. In Two Sum II each step drops one value, because a sum that is too small only proves the left value is hopeless.

Method 1: mirror check from both ends (Valid Palindrome)

The template as a mirror check, taken line for line from the notebook's is_palindrome_twoptr. Each outer pass skips non-alphanumerics on both sides, compares the two characters lowercased, and steps both pointers in on a match. One mismatch ends it.

def is_palindrome_twoptr(s: str) -> bool: i, j = 0, len(s) - 1 # one pointer at each end while i < j: # walk them toward the middle while i < j and not s[i].isalnum(): i += 1 # skip non-letters/digits on the left while i < j and not s[j].isalnum(): j -= 1 # skip non-letters/digits on the right if s[i].lower() != s[j].lower(): # mirror characters must match (ignore case) return False # mismatch -> not a palindrome i += 1; j -= 1 # both matched -> step inward return True # met in the middle with no mismatch

Key mental model

Fold the string in half. Each outer pass lays one character from the left on top of its mirror from the right. Spaces and punctuation are invisible, so each pointer slides past them on its own.

Common mistake

Dropping i < j from the skip loops. On a string of only punctuation, like " " or ",.", the left pointer would run off the end.

Why two pointers instead of a copy

The notebook's first approach builds a cleaned, lowercased copy and compares it with its reverse: also O(n) time, but O(n) extra memory. Two pointers read the original string in place: O(1) memory.

Method 2: let the sum pick the side (Two Sum II - Input Array Is Sorted)

The template in its purest form, from the notebook's two_sum_ii_two_pointers, traced on numbers = [1, 3, 4, 5, 7, 10, 11], target = 9. Now only one pointer moves per step, because a sum that is too small proves only that the left value is hopeless (even the largest partner left cannot lift it to 9), and a sum that is too big proves only that the right value is hopeless.

def two_sum_ii_two_pointers(numbers: List[int], target: int) -> List[int]: lo, hi = 0, len(numbers) - 1 # one pointer at each end while lo < hi: s = numbers[lo] + numbers[hi] if s == target: return [lo + 1, hi + 1] # 1-indexed answer if s < target: lo += 1 # numbers[lo] is too small for every partner left: drop it else: hi -= 1 # numbers[hi] is too big for every partner left: drop it return []

Key mental model

The sum is a dial. Moving lo right can only turn it up; moving hi left can only turn it down. Too low, turn it up; too high, turn it down. Sorted order is what makes the dial one-directional.

Common mistake

Returning [lo, hi]. This problem counts positions from 1, so the answer is [lo + 1, hi + 1] = [3, 4], not [2, 3].

Why not a hash map

The notebook's hash map approach is also O(n) time, but it stores up to n values, and the problem demands constant extra space. Two integers do the same job because the array is sorted.

Edge cases you should test

Case A: nothing alphanumeric

s = " "

Valid Palindrome = True

i = j = 0, so while i < j never runs. An empty cleaned string counts as a palindrome. The i < j guard inside the skip loops is what keeps longer all-punctuation strings in bounds.

Case B: a digit and a letter

s = "0P"

Valid Palindrome = False

Both characters are alphanumeric, so nothing is skipped. '0' != 'p' after lowercasing. Digits count as real characters, not as punctuation.

Case C: the mismatch hides behind a space

s = "race a car"

Valid Palindrome = False (stops at i = 3, j = 5: 'e' vs 'a')

r/r, a/a and c/c match; then j skips the space at index 6 and the pair 'e' / 'a' fails.

Case D: the smallest possible input

numbers = [-1, 0], target = -1

Two Sum II = [1, 2]

The very first sum, -1 + 0, is the answer. Negative values change nothing: the array is still sorted, so the dial still turns one way.

Case E: repeated values

nums = [0, 0, 0, 0] (3Sum)

3Sum = [[0, 0, 0]]

Without the neighbour skips (equal anchors, and equal lo / hi values after a hit) the same triplet would be reported more than once.

How to derive this in an interview

Reasoning path

The brute force checks every pair: O(n²).

The input is sorted (or symmetric, or limited by the shorter side), so comparing the two extremes tells me something about one of them for every partner.

That end can never be part of a better answer, so I drop it and keep the other.

Each step drops at least one element, so at most n - 1 steps: O(n) time, two indices of memory.

What to say out loud

  • "The array is sorted and I need a pair, so I'll put one pointer at each end."
  • "If the sum is too small, the left value can't work with anything that's left, so I move it right; too big, I move the right one left."
  • "For a palindrome I compare mirror characters and skip anything that isn't a letter or digit."
  • "Each step discards an element for good: O(n) time, O(1) extra space, versus O(n²) for all pairs."

Common beginner coding mistakes

Valid Palindrome

  • Forgetting .lower(), so 'T' and 't' look different.
  • Skipping punctuation on only one side.
  • Leaving i < j out of the skip loops, so the pointers run past each other or off the string.
  • Treating digits as punctuation: "0P" must be False.

Two Sum II and the sorted-pair family

  • Returning 0-based indices when the problem is 1-indexed.
  • Moving both pointers after a miss: only the side that was proven useless may move.
  • Looping with lo <= hi, which pairs an element with itself.
  • In 3Sum, forgetting to skip equal neighbours, which repeats triplets.

Practice questions

Try each in your head first. Open the hint, then the answer, only after you commit to a guess. Each links to the problem's interactive page.

Practice 1 — Two Sum II: numbers = [2, 7, 11, 15], target = 9

Hint: the first sum is 2 + 15. Which pointer moves?

Answer: 17 > 9, so hi moves to 11 (13 > 9), then to 7: 2 + 7 = 9, return [1, 2]. Compare it with the brute force and hash map on the Two Sum II page.

Practice 2 — 3Sum: nums = [-1, 0, 1, 2, -1, -4]

Hint: sort to [-4, -1, -1, 0, 1, 2], then for each anchor run Method 2 on the rest with target -anchor. Skip the second -1 anchor.

Answer: [[-1, -1, 2], [-1, 0, 1]]. Anchor -4 finds nothing (the largest pair is 1 + 2 = 3 < 4); anchor -1 finds both triplets. Step through it: 3Sum.

Practice 3 — Container With Most Water: why move the shorter wall in [1, 8, 6, 2, 5, 4, 8, 3, 7]?

Hint: area = shorter wall × width. What happens to the area if you keep the shorter wall and the width shrinks?

Answer: it can only shrink, so the shorter wall is finished and can be dropped. The first step drops height 1 (area 8); the second pair, heights 8 and 7, gives the answer min(8, 7) × 7 = 49. See Container With Most Water.

Practice 4 — Trapping Rain Water: height = [4, 2, 0, 3, 2, 5]

Hint: left_max = 4 < right_max = 5 from the start. Which side keeps moving, and what water line does every bar it reaches get?

Answer: 9. The left pointer does all the work, and every inner bar fills to 4: 2 + 4 + 1 + 2 = 9. The interactive page traces the longer LeetCode example, where both sides move: Trapping Rain Water.

Final takeaway

Start at both ends, look at the pair, drop the end that is finished. Valid Palindrome drops both ends after a match; Two Sum II and 3Sum drop the side the sum proves hopeless; Container With Most Water and Trapping Rain Water drop the shorter or lower side. Same loop, one rule apart, and always O(n) steps with O(1) memory.
