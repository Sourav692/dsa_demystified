239 · Sliding Window Maximum

A frame of width k slides along the numbers. What is the biggest number inside the frame at each stop?

The problem, in plain words

Lay a frame that covers k numbers over the start of the list. Write down the largest number inside it. Slide the frame one step right and repeat until it reaches the end.

Think of a 3-day weather report: each day you list the hottest temperature of the last 3 days.
Example: nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3 → [3, 3, 5, 5, 6, 7].
inside the framenumber enteringnumber leaving / thrown awaythe frame's maximum

answer so far

The solutions below use a smaller input, nums = [5, 4, 3, 2, 6, 1], k = 3 → [5, 4, 6, 6], because on it every move of the fast algorithm happens at least once.

Solution 1 — Brute force: rescan every frame

For each position of the frame, look at all k numbers inside and take the biggest. Simple, but neighbouring frames share k - 1 numbers and we look at them again every time.

answer so far

Speed & memory: k numbers per frame, about n frames — O(n·k) time (about 4x slower per doubling when k = n/2); O(k) memory for the slice.

Solution 2 — Better: a max-heap that cleans up lazily

A heap always hands you its biggest item in one look. Push every number as (value, index). A heap can't cheaply remove a number from the middle, so when one slides out of the frame we just leave it there. Only when an old number sits on top do we throw it away. Old numbers buried lower down do no harm.

heap items as value@index, biggest first (red = already outside the frame, still stored)

answer so far

Speed & memory: each push or pop costs O(log n) — O(n log n) time; stale items can pile up — O(n) memory.

Solution 3 — The smart way: a line of candidates that only gets smaller

If a newer number is at least as big as an older one, the older one can never be a frame's maximum again: the newer one stays in the frame longer and beats it. So throw it away. Keep the survivors in a deque (a line you can add to or remove from at both ends), stored by index, biggest at the front. The front is always the answer. When the front's index slides out of the frame, drop it.

deque, front first, as value@index

answer so far

Speed & memory: every index joins the deque once and leaves at most once — O(n) time in total, even when one step throws away several; the deque holds at most k indices — O(k) memory.

When you'd use this

See "maximum (or minimum) of every window of size k"? The frame has a fixed width, so slide it one step at a time. A plain running total can't forget a maximum that leaves, so keep a deque of the candidates that can still win.
