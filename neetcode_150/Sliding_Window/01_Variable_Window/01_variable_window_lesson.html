Variable Window

Keep a window s[left..right] over a string or array. Move right one step at a time to grow it, and move left forward only when the window breaks the rule (or, for "shortest" problems, while it still keeps the rule). Each index enters the window once and leaves once, so a problem that looks like "check every substring" becomes one O(n) pass.

Core idea: grow right, shrink left, never move backwards Method 1: longest valid window (set) Method 2: shortest valid window (need / missing) Interactive traces synced to code

Problems in this pattern: Best Time to Buy and Sell Stock · Longest Substring Without Repeating Characters · Longest Repeating Character Replacement · Minimum Window Substring · pattern notes (README)

Canonical example

Longest Substring Without Repeating Characters, s = "abcabcbb"

Answer = 3

Why this pattern matters

Longest stretch that obeys a rule

The longest run of a playlist with no song repeated, the longest period a sensor stayed within limits: you want the biggest contiguous range that stays valid.

Shortest stretch that covers a need

The smallest snippet of a document that contains every search term is exactly Minimum Window Substring: grow until covered, then trim.

One template, four problems

All four problems in this folder use the same loop. Only the window's bookkeeping (a set, a count map, a need counter, a running minimum) and the validity test change.

Instructor note: the brute force checks every (start, end) pair, O(n²) windows. The variable window reuses the work: when right moves, the window keeps everything it already knew and updates its state in O(1).

What is a variable window?

Simple definition

Two indices, left and right, mark a contiguous range. A small piece of state (a set, a count map, a counter) always describes what is inside that range. right moves forward every loop; left moves forward only when the rule says so. Neither index ever moves back.

The tell in a problem statement

"Longest / shortest substring or subarray" (contiguous) with a property: "without repeating characters", "after at most k changes", "containing all characters of t". The property must be checkable from the window's state alone.

Beginner shortcut: ask "if a window breaks the rule, does every bigger window that contains it also break it?" If yes, shrinking from the left is safe, and the variable window works. Best Time to Buy and Sell Stock is the degenerate case: left is the cheapest day so far and simply jumps to any new low.

Step-by-step thinking process

1

Spot the window

Contiguous range plus "longest" or "shortest". Brute force would be every pair of ends.

2

Pick the state

What must you know about the window to test the rule in O(1)? A set, a count dict, a need counter with missing.

3

Grow, then fix

Add s[right] to the state. Longest: shrink while invalid. Shortest: shrink while valid.

4

Record at the right moment

Longest: after the shrink, the window is valid, so update best. Shortest: inside the shrink loop, before each drop.

How the input becomes a window and its state

The input is just a string. The algorithm never builds substrings; it keeps two indices and a summary of the characters between them. For Method 1 that summary is the set seen, which always equals the set of characters in s[left..right].

Input string

s = "abcabcbb" 01234567
→

Window + state (after right = 5)

left = 3, right = 5 window = s[3:6] = "abc" seen = {a, b, c}

right moves one step every loop

The new character s[right] is about to join the window.

If it would break the rule, left moves first

Each move removes s[left] from the state, until the new character can join safely.

The new character joins the state

seen.add(s[right]). The window s[left..right] is valid again.

Record the answer

right - left + 1 is the window's length. Keep the largest.

Critical point: the state must be updated on both moves: add on right, remove on left. Forget the remove and the set describes characters that already left the window.

Method 1: longest valid window (Longest Substring Without Repeating Characters)

The template in its plainest form, taken line for line from the notebook's length_window_set. The rule is "no character twice", the state is a set, and the window shrinks while invalid: while the incoming character is already inside.

def length_window_set(s: str) -> int: seen = set() # characters currently inside the window left = best = 0 # left edge of the window; best length so far for right in range(len(s)): # right edge sweeps across the string while s[right] in seen: # new char already inside -> shrink from the left seen.remove(s[left]) # drop the leftmost char left += 1 # move the left edge right seen.add(s[right]) # now safe to add the new character best = max(best, right - left + 1) # update the best window length return best

Key mental model

The window is a caterpillar: the head (right) always crawls forward, the tail (left) catches up only when the body breaks the rule. Over the whole run left moves at most n times, so the inner while costs O(n) in total, not per step.

Common mistake

Using if instead of while to shrink. At step 10 (right = 6, 'b') the window is "abc" and the repeat sits in the middle: two drops, 'a' then 'b', are needed before 'b' can join.

Why a set, and the map refinement

Membership in a set is O(1) on average. The notebook's optimal version, length_window_map, stores each character's last index and jumps left = last[c] + 1 in one move (guarded by last[c] >= left); same O(n), fewer steps.

Method 2: shortest valid window (Minimum Window Substring)

The same loop, with the shrink condition flipped. Now the goal is the shortest window that covers every character of t, so the window grows until it is valid (missing == 0) and then shrinks while it stays valid, recording the best before each drop. Code from the notebook's min_window_slide, traced on s = "ADOBECODEBANC", t = "ABC".

def min_window_slide(s: str, t: str) -> str: if not t or not s: return "" need = Counter(t) # remaining count needed for each character missing = len(t) # total characters still to cover (with repeats) left = 0 # left edge of the window best = (float("inf"), 0, 0) # (window length, start, end+1) of the best so far for right, c in enumerate(s): # right edge sweeps across s if need[c] > 0: # c is a character we still needed missing -= 1 # one fewer to cover need[c] -= 1 # (can go negative for extra copies) while missing == 0: # window covers all of t -> try to shrink it if right - left + 1 < best[0]: best = (right - left + 1, left, right + 1) # record a smaller window need[s[left]] += 1 # about to drop the leftmost char if need[s[left]] > 0: # dropping it breaks coverage missing += 1 # we now need that character again left += 1 # move the left edge right return "" if best[0] == float("inf") else s[best[1]:best[2]]

Key mental model

Longest problems shrink to repair an invalid window and record after. Shortest problems shrink to improve a valid window and record before each drop. Same two pointers, opposite reason to move left.

Common mistake

Decrementing missing for every needed letter, even extra copies. At step 11 ('B' again) need['B'] is already 0, so missing must stay 1. Only need[c] > 0 counts.

Why one counter

missing turns "does the window cover t?" into one comparison. Re-checking every letter's count each step is what makes the brute force O(n²·m).

Edge cases you should test

Case A: empty string

Longest Substring, s = ""

Answer = 0

The for loop never runs, so best keeps its starting value 0. No special case is needed.

Case B: every character the same

Longest Substring, s = "bbbbb"

Answer = 1

Every new 'b' forces one drop. The window never grows past length 1, and left still moves only n times in total.

Case C: a remembered index that is already outside the window

Longest Substring with the last-seen map, s = "abba"

Answer = 2

At the final 'a', last['a'] = 0 but left is already 2. Without the last[c] >= left guard, left would jump back to 1 and the answer would be 3, which is wrong.

Case D: t needs more copies than s has

Minimum Window Substring, s = "a", t = "aa"

Answer = ""

missing only reaches 1, the shrink loop never runs, and best stays at infinity, so the function returns the empty string.

Case E: no profitable trade

Best Time to Buy and Sell Stock, prices = [7, 6, 4, 3, 1]

Answer = 0

Every day is a new minimum, so the window restarts each day and price - min_price is always 0. Starting best at 0 (not -inf) means "don't trade".

How to derive this in an interview

Reasoning path

The answer is a contiguous range, and brute force tries all O(n²) of them.

If a window breaks the rule, so does every window that contains it. So once a start fails, moving it forward is safe.

Then both ends only move forward: right once per loop, left at most n times overall.

Choose the state that answers "is the window valid?" in O(1), and decide whether to record after shrinking (longest) or before each drop (shortest).

What to say out loud

  • "This is a longest-substring question with a rule I can check incrementally, so I'll use a variable sliding window."
  • "I keep a set of the characters inside s[left..right]. Each step I add s[right]; while it is a repeat, I remove s[left] and move left."
  • "After the shrink the window is valid, so I update the best length with right - left + 1."
  • "Each index enters and leaves at most once: O(n) time, O(n) space for the set (O(1) for a fixed alphabet)."

Common beginner coding mistakes

Longest-window problems

  • Shrinking with if instead of while, so the window can stay invalid.
  • Updating best before the shrink, recording an invalid window.
  • Forgetting to remove s[left] from the state when left moves.
  • With a last-seen map, jumping left backwards to a stale index (missing last[c] >= left).

Shortest-window problems

  • Shrinking before the window is valid, or recording after the drop that broke it.
  • Decrementing missing for extra copies of a letter.
  • Not restoring need[s[left]] when the left character leaves.
  • Returning a window when none was found: check best is still infinity.

Practice questions

Try each in your head first. Open the hint, then the answer, only after you commit to a guess. Each links to the problem's interactive page.

Practice 1 — Best Time to Buy and Sell Stock: prices = [7, 1, 5, 3, 6, 4]. Where is the window?

Hint: treat left as the buy day and right as today. When does left move?

Answer: 5. min_price is prices[left]. It only moves when a cheaper day appears (day 1, price 1), and then it jumps straight to that day, because any window starting earlier is now worse. Best window: buy day 1, sell day 4, 6 - 1 = 5. Step through it: Best Time to Buy and Sell Stock.

Practice 2 — Longest Repeating Character Replacement: s = "AABABBA", k = 1

Hint: a window is valid while (window length) - (count of its most common letter) <= k.

Answer: 4. "AABA" (indices 0 to 3) needs one change. From right = 4 on, each step makes the window need 2 changes, so left moves once and the length stays 4. Walkthrough: Longest Repeating Character Replacement.

Practice 3 — Minimum Window Substring: s = "aa", t = "aa"

Hint: need['a'] starts at 2 and missing at 2. When does missing hit 0?

Answer: "aa". Both reads decrement missing; at right = 1 it is 0, the window "aa" is recorded, and dropping the first 'a' breaks coverage at once. See the trace on Minimum Window Substring.

Practice 4 — Longest Substring Without Repeating Characters: s = "pwwkew"

Hint: the second 'w' forces left past the first one.

Answer: 3 ("wke"). "pwke" is not a substring, so it does not count. Compare the set and map versions on Longest Substring Without Repeating Characters.

Final takeaway

Grow right every step, move left only when the rule says so, and keep a state that tests the rule in O(1). For "longest", shrink while invalid and record after. For "shortest", shrink while valid and record before each drop. Best Time to Buy and Sell Stock is the same idea with the shrink collapsed into a jump to the new minimum.
