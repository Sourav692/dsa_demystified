Top K

Keep a heap capped at k items whose root is the weakest of the kept ones. Every new item is pushed; whenever the heap holds k + 1, the root is popped. What remains is the k best items, and the root is the k-th best: O(n log k) time and only O(k) memory.

Core idea: push, then trim back to k Method 1: min-heap (Kth Largest in a Stream) Method 2: max-heap by distance (K Closest Points) Interactive traces synced to code

Problems in this pattern: Kth Largest Element in a Stream · K Closest Points to Origin · Kth Largest Element in an Array · pattern notes (README)

Canonical example

Kth Largest Element in a Stream, k = 3, nums = [4, 5, 8, 2], then add 3, 5, 10, 9, 4

add() returns 4, 5, 5, 8, 8

Why this pattern matters

Leaderboards and rankings

"Show the top 10 scores" over millions of players: you only ever need to remember 10 of them, not sort everyone each time a score comes in.

Nearest results

"The 5 closest restaurants" or "the k most similar documents": score every candidate, keep the best k, throw the rest away as you go.

Streams that never end

Monitoring the k slowest requests of the day: data arrives forever, so sorting the whole history is not an option. A size-k heap uses fixed memory.

Instructor note: the whole pattern is two lines (heappush, then heappop if the size is over k) plus one decision: which direction the heap points. Get the direction right and every Top K problem is the same loop.

What is the Top K pattern?

Simple definition

A heap is a list arranged as a tree where every parent is no bigger than its children, so the smallest item is always at index 0 and can be removed in O(log size). Top K keeps such a heap at at most k items: the root is the weakest of the k kept items, so it is the one to throw out when a better item arrives.

The tell in a problem statement

"k-th largest", "k-th smallest", "top k", "k closest", "k nearest", "return in any order", or values that arrive over time ("a stream", "after each add"). Also "can you do it without sorting?" next to a k-th element question.

Beginner shortcut: the root must be the item you would evict next. For the k largest, evict the smallest, so use a min-heap. For the k smallest, evict the largest, so use a max-heap. Python's heapq is a min-heap only, so a max-heap means pushing negated keys.

Step-by-step thinking process

1

Spot "k of something"

Only the best k items matter, or just the k-th one. Sorting all n is more than you need.

2

Pick the direction

k largest → min-heap. k smallest → max-heap (negate the key). Put the key first in a tuple.

3

Push, then trim

For each item: heappush; if len(heap) > k, heappop. The heap never grows past k + 1.

4

Read the answer

heap[0] is the k-th best item; the whole heap is the k best, in no particular order.

How the input becomes a heap

The input is just values arriving one by one. The heap is an ordinary Python list that heapq keeps in heap order: index i has children at 2i + 1 and 2i + 2, and every parent is <= its children. Here is the canonical example's constructor feeding [4, 5, 8, 2] into a heap capped at k = 3.

Input

k = 3 nums = [4, 5, 8, 2]
→

Heap list after the constructor

heap = [4, 5, 8] index 0: 4 (root, the minimum) index 1: 5 (left child of 4) index 2: 8 (right child of 4)

Push 4

heap = [4]. Size 1, not over k.

Push 5, then 8

heap = [4, 5, 8]. Size 3 = k. The root 4 is the smallest of the three largest.

Push 2

It is smaller than its parent, so it sifts up to the root: heap = [2, 4, 8, 5]. Size 4 > k.

Pop the root

2 leaves and the list re-forms as [4, 5, 8]. Anything smaller than the root can never be in the top 3.

Critical point: the heap is not sorted. [5, 10, 8] is a valid heap: only the root's position is guaranteed. That is exactly enough, because the root is the only value we ever read or remove.

Method 1: size-k min-heap (Kth Largest Element in a Stream)

The template itself, taken line for line from the notebook's KthLargest class. The constructor feeds nums through the same add method as streamed values, so there is one code path. Each step below is one heap operation; the heap arrays are what heapq actually stores.

class KthLargest: def __init__(self, k: int, nums: List[int]): self.k = k self.heap = [] # min-heap of the k largest values seen for x in nums: self.add(x) # same push-then-trim step as a streamed value def add(self, val: int) -> int: heapq.heappush(self.heap, val) if len(self.heap) > self.k: # one too many: the root is no longer top-k heapq.heappop(self.heap) return self.heap[0] # smallest of the top k = k-th largest

Key mental model

The root is a bouncer at a club with k seats. Anyone who walks in sits down; if the club is over capacity, the weakest person (the bouncer's spot, the root) is shown out. Whoever holds the root spot afterwards is the k-th best.

Common mistake

Using a max-heap of every value and popping k - 1 times per query. It is correct, but it stores all n values and re-does the pops on every add.

Why a heap

The only questions asked are "what is the smallest kept value?" and "remove it". A heap answers the first in O(1) and the second in O(log k). A sorted list would answer them too, but inserting into it costs O(k) shifts.

Method 2: size-k max-heap by distance (K Closest Points to Origin)

Same loop, opposite direction. We want the k smallest distances, so the item to evict is the farthest kept point: a max-heap. heapq only gives a min-heap, so the key is -(x² + y²): the farthest point has the most negative key and sits at the root. Code from the notebook's k_closest_heap, traced on points = [[3,3],[5,-1],[-2,4],[1,-1],[0,2]], k = 2.

def k_closest_heap(points: List[List[int]], k: int) -> List[List[int]]: heap = [] # max-heap via negated distance: root = farthest kept for x, y in points: heapq.heappush(heap, (-(x * x + y * y), x, y)) if len(heap) > k: # one too many: drop the farthest heapq.heappop(heap) return [[x, y] for _, x, y in heap] # any order is accepted

Key mental model

Same club, different bouncer: for "closest" the weakest member is the one farthest away, so the farthest kept point must sit at the root. Negating the key turns heapq's min-heap into that max-heap.

Common mistake

Forgetting the minus sign. A plain min-heap capped at k evicts the closest point each time and returns the k farthest.

Why the tuple order matters

heapq compares tuples item by item, so the key goes first: (-dist², x, y). Squared distance keeps the order of true distance with exact integer math, so no sqrt is needed.

Edge cases you should test

Case A: the stream starts short

KthLargest(2, [0]), then add(-1), add(1)

Returns -1, then 0

The heap holds only one value after the constructor. The trim only fires when the size is over k, so nothing is lost; by the time add returns, the heap holds k values (the problem guarantees it). A notebook test case.

Case B: k = 1, the maximum so far

KthLargest(1, []), then add(-3), add(-2), add(-4)

Returns -3, -2, -2

A size-1 min-heap keeps the largest value seen. Negative numbers need no special handling. A notebook test case.

Case C: duplicates each count

nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4 (Kth Largest Element in an Array)

Answer = 4

Biggest first: 6, 5, 5, 4. The two 5s take two places. The heap keeps duplicates naturally; do not de-duplicate with a set.

Case D: k equals the number of items

points = [[0, 1], [1, 0]], k = 2 (K Closest Points)

Answer = both points, any order

The heap never exceeds k, so the trim never runs and every point is returned. A notebook test case.

How to derive this in an interview

Reasoning path

Sorting everything answers it in O(n log n). Do I need the full order? No, only the best k.

Which item do I throw away when a better one arrives? The weakest of the kept k. I need it at hand: a heap root.

"Weakest" for the k largest is the smallest, so a min-heap; for the k smallest, a max-heap with negated keys.

Push, trim when over k, read heap[0]. O(n log k) time, O(k) memory, and it works on a stream.

What to say out loud

  • "I only need the top k, not the full order, so I'll keep a heap of size k instead of sorting."
  • "For the k largest I use a min-heap, so the root is the smallest kept value, which is exactly the one to evict."
  • "Each item costs one push and at most one pop on a heap of size k + 1: O(n log k) time, O(k) space."
  • "If the whole array is in memory and I may reorder it, quickselect with a random pivot is O(n) on average."

Common beginner coding mistakes

Kth Largest (stream and array)

  • Using a max-heap of all values: O(n) memory and extra pops per query.
  • Trimming with >= instead of >, so the heap holds only k - 1 values and the root is the wrong rank.
  • Reading heap[0] before the heap has k values.
  • Quickselect with a fixed pivot (sorted input becomes O(n²)), or mixing up index k and index n - k.

K Closest Points

  • Forgetting to negate the distance, which keeps the k farthest points.
  • Putting the distance last in the tuple, so the heap orders by x.
  • Taking sqrt: slower, and floats are not needed to compare distances.
  • Testing the output in a fixed order when "any order" is allowed.

Practice 1 — Kth Largest Element in a Stream: KthLargest(4, [7, 7, 7, 7, 8, 3]), then add 2, 10, 9, 9

Hint: after the constructor the heap holds the 4 largest of the starting values. Which value is at the root?

Answer: 7, 7, 7, 8. The constructor keeps 7, 7, 7, 8 (one 7 and the 3 are popped), so the root is 7. Adding 2 changes nothing; 10 and the first 9 each push out a 7, but a 7 is still the smallest kept; the second 9 pushes out the last 7, so the root becomes 8. Step through the same template on Kth Largest Element in a Stream.

Practice 2 — K Closest Points to Origin: points = [[1, 3], [-2, 2]], k = 1

Hint: compute x² + y² for each point; which key ends up at the root of a size-1 max-heap?

Answer: [[-2, 2]]. The keys are -10 and -8. After pushing both, the heap is over k, so the root -10, the point (1, 3), is popped. Compare all three approaches on K Closest Points to Origin.

Practice 3 — Kth Largest Element in an Array: nums = [3, 2, 1, 5, 6, 4], k = 2, with quickselect

Hint: the target index in ascending order is n - k = 4. After one 3-way partition around pivot 3, which side holds index 4?

Answer: 5. Around pivot 3 the array becomes [2, 1 | 3 | 6, 4, 5]; index 4 is on the right, so only [6, 4, 5] is kept. Partitioning that around pivot 5 puts 5 at index 4. Watch every swap on Kth Largest Element in an Array.

Practice 4 (follow-up variant of Kth Largest in an Array) — the 2nd smallest of [3, 2, 1, 5, 6, 4] with a heap

Hint: which direction must the heap point now, and what goes into heapq?

Answer: 2. Use a max-heap of size 2 by pushing -x; after all six values it holds -2 and -1, and the root -heap[0] = 2 is the 2nd smallest. It is the K Closest Points direction applied to plain numbers; see K Closest Points to Origin for the negated-key trace.

Final takeaway

Push, and if the heap holds more than k, pop the root. The root is always the weakest of the kept items, so pick the heap's direction to match: a min-heap for the k largest, a max-heap (negated keys) for the k smallest. Kth Largest in a Stream reads the root after each add; K Closest Points returns the whole heap; Kth Largest in an Array reads the root once, or uses quickselect for O(n) on average.
