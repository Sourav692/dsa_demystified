703 · Kth Largest Element in a Stream

Scores keep arriving. After each one, report the k-th best score so far.

The problem, in plain words

Think of a leaderboard that only cares about one spot: the k-th place. Every time a new score comes in, you must say who is in k-th place now. You build a small class with an add(val) method that answers that question after each new score.

Example: k = 3, start with [4, 5, 8, 2], then add 3, 5, 10, 9, 4 → returns 4, 5, 5, 8, 8.
Duplicates count: in [8, 5, 5, 4] both the 2nd and the 3rd place are 5.
just arrivedabove k-th placek-th place (the answer)thrown away

The leaderboard is drawn best first. Only the green box is ever reported.

Solution 1 — Brute force: re-sort everything on every add

Keep every score in a list, in the order it arrived. On each add, append the score, sort a copy of the whole list, and read the value k places from the end.

Speed & memory: every call sorts the whole history again — O(n log n) per add, O(n) memory. The notebook measured about 4–5× per doubling over n adds.

Solution 2 — Keep the list sorted with bisect.insort

Sort once at the start. After that, drop each new score straight into its sorted slot (binary search finds the slot). The answer is always k places from the end. But to make room, every value to the right of the slot has to shift one place.

Speed & memory: finding the slot is fast (O(log n)), but the shift makes each add O(n); memory stays O(n).

Solution 3 — The smart way: a min-heap that holds only the top k

A min-heap is a pile where the smallest value is always on top and can be read instantly. Keep only the k best scores in it. A new score joins the pile; if the pile now has k + 1 scores, the one on top (the weakest) leaves. The top of the pile is then the k-th best score.

returned by add so far

Speed & memory: the pile never holds more than k + 1 scores — O(log k) per add, O(k) memory. Everything below the top k is forgotten for good.

When you'd use this

See "k-th largest", "top k" or "after each new value"? Keep a min-heap capped at k: push, pop if it holds k + 1, and read the top.
