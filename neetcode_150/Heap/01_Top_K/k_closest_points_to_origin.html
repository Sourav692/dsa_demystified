973 · K Closest Points to Origin

Out of many points on a map, keep the k that are nearest to the center.

The problem, in plain words

You are standing at (0, 0). Around you are points, like shops on a map. Return the k shops that are closest to you, in any order.

Distance is the straight line √(x² + y²). We can skip the square root: comparing x² + y² ranks the points in exactly the same order. We call it dist².
Example used on this page: [[3,3],[5,-1],[-2,4],[1,-1],[0,2]], k = 2 → [[1,-1],[0,2]].

Solution 1 — Brute force: find the nearest remaining point, k times

Scan every point and take the closest one. Then scan again, skipping the ones already taken, and take the next closest. Repeat k times.

Speed & memory: k full scans of n points — O(n·k), which is O(n²) when k is near n (the notebook measured ≈4× per doubling with k = n/2); O(n) memory for the "taken" marks.

Solution 2 — Sort everyone by distance

Work out every point's dist², sort all points by it, and keep the first k. Simple and correct, but it puts all n points in order when we only need the nearest k.

Speed & memory: one sort — O(n log n) time, O(n) memory for the sorted copy.

Solution 3 — The smart way: a max-heap that keeps only the k nearest

Keep a small pile of at most k points with the farthest one on top (a max-heap by distance). Each new point joins the pile; if it now holds k + 1 points, throw out the one on top — the farthest. Python's heapq only puts the smallest on top, so we store -dist²: the farthest point gets the most negative key.

Speed & memory: one push and at most one pop per point on a pile of size k + 1 — O(n log k) time, O(k) memory.

When you'd use this

See "k closest", "k nearest" or "k smallest by some score"? Keep a heap of size k with the worst kept item on top: for the k smallest that is a max-heap (negate the key in Python).
