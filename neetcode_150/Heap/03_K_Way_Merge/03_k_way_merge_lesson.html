K Way Merge

You have k inputs and each one is already sorted. The next item of the merged output must be one of the k current fronts, so keep exactly those fronts in a min-heap. Pop the smallest, then push the next item from the same input. The heap never holds more than k items.

Core idea: a heap of the k fronts Method 1: Merge k Sorted Lists Method 2: Design Twitter news feed Interactive traces synced to code

Problems in this pattern: Merge k Sorted Lists · Design Twitter · pattern notes (README)

Canonical example

Merge k Sorted Lists, lists = [[1,4,5], [1,3,4], [2,6]]

Answer = [1, 1, 2, 3, 4, 4, 5, 6]

Why this pattern matters

Merging sorted files

Databases and sort tools sort data that does not fit in memory as many sorted chunks, then merge the chunks in one pass: a k-way merge.

Timelines and feeds

Every account's posts are already in time order. A feed is the newest few across the accounts you follow, which is a merge that stops early.

Many sorted streams

Log files from many servers, price ticks from many exchanges: each stream is ordered, and you want one ordered stream out.

Instructor note: the work is not in sorting. The inputs are already sorted. The work is in choosing, again and again, the best of k candidates, and a heap does that in O(log k).

What is a k-way merge?

Simple definition

Merging two sorted lists compares their two fronts and takes the smaller. A k-way merge does the same with k fronts. Comparing all k each time costs O(k) per item; a min-heap of the fronts finds the smallest in O(log k). You output N items in total, so the merge costs O(N log k).

The tell in a problem statement

Several sorted inputs and one ordered answer across them: "merge k sorted lists", "each row is sorted", "the 10 most recent tweets from the people you follow", "kth smallest across k sorted lists".

Beginner shortcut: the heap entry is (key, source index, item). The key orders the heap. The source index tells you which list to advance after a pop, and it settles ties, so Python never has to compare two ListNode objects (it cannot, and would raise TypeError).

Step-by-step thinking process

1

Spot k sorted sources

Lists, rows, or per-user timelines that are each already in order.

2

Seed the heap

Push the front of every non-empty source as (key, i, item).

3

Pop, then refill

Pop the smallest key, output it, and push the next item from the same source i.

4

Stop

When the heap is empty, or as soon as you have as many items as you need (10 for a feed).

How the input becomes a heap of fronts

The input is k sorted sources. The heap does not hold all of their items, only one per source: its current front. Everything else waits in its own list until its turn.

Input: k sorted lists

list 0: 1 -> 4 -> 5 list 1: 1 -> 3 -> 4 list 2: 2 -> 6
→

Heap: one entry per list

(1, 0, node 1 of list 0) top (1, 1, node 1 of list 1) (2, 2, node 2 of list 2)

Read the front of list 0

Push (1, 0, node). The heap has one entry.

Read the front of list 1

Push (1, 1, node). Same value 1, so the index decides the order: (1, 0, ...) stays on top.

Read the front of list 2

Push (2, 2, node). The heap now holds exactly k = 3 entries.

Skip empty sources

A None list (an empty list on LeetCode) has no front, so if node: leaves it out.

Critical point: for Design Twitter the sources are the user plus each followee, the "front" is each user's newest tweet (the end of their list), and the key is -time because heapq only pops the smallest.

Method 1: the template on linked lists (Merge k Sorted Lists)

Code from the notebook's merge_k_heap, line for line. Lists are numbered by their index i in lists: 0, 1, 2. Popped nodes are relinked onto cur, not copied.

def merge_k_heap(lists): heap = [] # min-heap of the current front node of each list for i, node in enumerate(lists): if node: heapq.heappush(heap, (node.val, i, node)) # (value, list-index tiebreak, node) dummy = ListNode(); cur = dummy while heap: val, i, node = heapq.heappop(heap) # smallest available value across all lists cur.next = node; cur = node # attach it to the merged list if node.next: heapq.heappush(heap, (node.next.val, i, node.next)) # push that list's next node return dummy.next

Key mental model

Each list is a queue of people in height order. Only the person at the front of each queue stands in the heap. Whoever leaves the heap is replaced by the next person from their own queue.

Common mistake

Pushing (node.val, node). Steps 1 and 4 have ties on the value; Python then compares the nodes and raises TypeError: '<' not supported between instances of 'ListNode' and 'ListNode', as the notebook shows.

Why a heap of size k

Scanning the k fronts for the minimum costs O(k) per node, O(N·k) in total. The heap costs O(log k) per node: O(N log k), with only O(k) extra space.

Method 2: merge newest-first and stop at 10 (Design Twitter)

Each user's tweets are stored as (time, tweetId) in posting order, so each user's list is sorted by time for free. The feed merges the user's list with every followee's list, from the newest end, with the key -time, and stops after 10 tweets. Code from the notebook's Twitter.getNewsFeed, traced on its Example 2: user 1 follows users 2 and 3.

def getNewsFeed(self, userId: int) -> List[int]: heap = [] for uid in self.following[userId] | {userId}: # the k sources: followees + the user themself tl = self.tweets[uid] if tl: t, tid = tl[-1] # newest tweet of this source = end of its list heap.append((-t, tid, uid, len(tl) - 1)) # -t: heapq is a min-heap, we want the max time heapq.heapify(heap) # O(k) feed = [] while heap and len(feed) < 10: # stop after 10: the rest is never read _, tid, uid, i = heapq.heappop(heap) # most recent remaining tweet across all sources feed.append(tid) if i > 0: # same user has an older tweet: it joins the race t, nid = self.tweets[uid][i - 1] heapq.heappush(heap, (-t, nid, uid, i - 1)) return feed

Key mental model

The same loop as Method 1, run backwards in time. "Front" means newest, "next" means the tweet at i - 1, and the loop may stop at 10 even when the heap still has entries.

Common mistake

Keying the heap on time instead of -time. heapq pops the smallest, so the feed would start with the oldest tweet, 11.

Why the merge beats sorting

The brute force sorts all T tweets of the user and followees on every call: O(T log T). The merge reads at most k + 10 entries: O(k + 10 log k). In the notebook the brute force roughly doubles per doubling of T; the heap stays flat.

Edge cases you should test

Case A: nothing to merge

lists = [] and lists = [[]] (a single empty list, None in Python)

Merged = [] in both cases

The if node: guard skips empty lists, so the heap starts empty and dummy.next is None. The notebook asserts both.

Case B: two fronts with the same value

lists = [[1,4,5], [1,3,4], [2,6]]: both list 0 and list 1 start with 1

(1, 0, node) pops before (1, 1, node)

With the index in the tuple, ties are settled by the list number. Without it, heappush raises TypeError because ListNode has no <.

Case C: the feed limit

User 1 posts tweets 0, 1, ..., 11 (12 tweets)

Feed = [11, 10, 9, 8, 7, 6, 5, 4, 3, 2]

while heap and len(feed) < 10 stops after 10 pops; tweets 1 and 0 are never read. A notebook assert covers this.

Case D: follow and unfollow yourself

post(1, 7), follow(1, 1), getNewsFeed(1), unfollow(1, 1), getNewsFeed(1)

Feed = [7], then still [7]

follow ignores followerId == followeeId, so tweet 7 is not listed twice; unfollow uses set.discard, so it neither hides your own tweets nor raises.

How to derive this in an interview

Reasoning path

Brute force first: put everything together and sort. Correct, but it throws away the fact that each input is already sorted.

The next output item must be one of the k fronts, so I only ever need to compare k candidates.

"Smallest of a changing set" means a min-heap: O(log k) per pop and push.

Heap entry (key, source index, item): the index finds the next item and breaks ties. If only the first few items are needed, stop early.

What to say out loud

  • "Each list is sorted, so the next smallest overall is one of the k heads."
  • "I'll keep the heads in a min-heap of (val, i, node); i breaks ties because nodes are not comparable."
  • "Pop the smallest, attach it, push that list's next node: O(N log k) time, O(k) space."
  • "For the Twitter feed, each user's tweets are already in time order, so I merge from the newest end with -time and stop after 10."

Common beginner coding mistakes

Merge k Sorted Lists

  • Pushing (val, node) without a tie-breaker: TypeError on the first equal value.
  • Forgetting to push the popped node's next, so each list contributes only its head.
  • Pushing every node up front: correct, but O(N) heap space and O(N log N) time.
  • Pushing None for an empty list, which crashes on .val.

Design Twitter

  • Leaving the user's own tweets out of the feed.
  • Keying on time instead of -time: the oldest tweets come out first.
  • Letting a user follow themselves, so their tweets appear twice.
  • Using set.remove in unfollow: KeyError when the user was not followed.

Practice questions

Try each in your head first. Open the hint, then the answer, only after you commit to a guess. Practice 3 and 4 are follow-up variants of Merge k Sorted Lists (LeetCode 378 and 632); they are not in this folder's notebooks.

Practice 1 — Merge k Sorted Lists: what is in the heap after the first three pops on [[1,4,5], [1,3,4], [2,6]]?

Hint: after each pop, only the popped node's own list gets a new front.

Answer: (3,1) (4,0) (6,2), and the merged list is [1, 1, 2]. The heap always holds one entry per unfinished list. Step through it on Merge k Sorted Lists.

Practice 2 — Design Twitter: post(1,5), follow(1,2), post(2,6), getNewsFeed(1), unfollow(1,2), getNewsFeed(1)

Hint: tweet 6 was posted after tweet 5, so it is newer.

Answer: [6, 5], then [5]. After the unfollow, user 2 is no longer a source, so the heap is seeded with user 1 only. This is LeetCode's example; see Design Twitter.

Practice 3 (variant, LeetCode 378) — Kth smallest in a sorted matrix: [[1,5,9],[10,11,13],[12,13,15]], k = 8

Hint: every row is a sorted list. Seed the heap with each row's first element as (val, row, col), pop k - 1 times, pushing (row, col + 1) after each pop.

Answer: 13. The pops come out as 1, 5, 9, 10, 11, 12, 13, so after 7 pops the heap's top is the 8th smallest, 13. Same loop as Merge k Sorted Lists, stopped early.

Practice 4 (variant, LeetCode 632) — Smallest range that contains one number from each list: [[4,10,15,24,26],[0,9,12,20],[5,18,22,30]]

Hint: the heap holds one front per list, so [heap minimum, current maximum front] always covers every list. Track the maximum as you push, and stop when the popped list runs out.

Answer: [20, 24]. The window contains 24 from list 0, 20 from list 1 and 22 from list 2. It is the k-way merge loop from Merge k Sorted Lists plus one running maximum.

Final takeaway

One front per sorted source in a min-heap; pop the best, push the next from the same source. Merge k Sorted Lists runs it until the heap is empty. Design Twitter runs it from the newest end with -time and stops after 10. Put a source index in every entry, so you know which list to advance and Python never compares the payloads.
