621 · Task Scheduler

A CPU runs one task per tick, but the same task needs a rest of n ticks before it can run again. How few ticks can it take?

The problem, in plain words

Think of a coffee machine that must cool down after each espresso of the same kind. You have a list of orders (letters). Each tick the machine makes one drink or waits. The same letter must be at least n ticks apart. Find the shortest timeline that makes every drink.

Example: tasks = [A, A, A, B, B, B], n = 2 → 8: A B idle A B idle A B. After an A, two other ticks must pass before the next A.
task runsidle (forced wait)current tick

Each box is one tick. Only 6 tasks, but 8 ticks: the two idles are forced by the cooldown.

Solution 1 — Brute force: tick by tick, check every task type

Keep, for each letter, how many copies are left and the first tick it is allowed again. At every tick, look at every letter and run the allowed one with the most copies left. If none is allowed, the tick is idle.

per letter: copies left · allowed from tick

Speed & memory: every tick scans all k letters: O(ticks · k) time, O(k) memory. With 26 letters that is fine, but if the number of task kinds grows with the input it becomes O(T²) (the notebook measures about 4× per doubling).

Solution 2 — The smart way: a max-heap of piles plus a cooldown line

Only how many copies each letter has matters, not its name. Put the counts in a max-heap (biggest pile at the front). Each tick, run one copy of the biggest pile. If copies remain, that pile waits in a cooldown line (a queue) with the tick it may come back. When the line's front is free again, it rejoins the heap. If the heap is empty, the CPU idles: jump the clock straight to when the line's front is free.

heap: copies left per letter (biggest first)

cooldown line: (copies left, released after tick)

Speed & memory: each task is one heap pop and at most one push: O(T log k) time; idle stretches are skipped in one jump. The heap and the line together hold at most one entry per letter: O(k) memory.

Solution 3 — Shortcut: count the frames

The most frequent letter decides the shape. With maxf copies of it, there are maxf - 1 full frames of n + 1 ticks, then a last frame holding one copy of every letter that ties for the most copies (count_max). Other tasks fill the gaps; if there are more tasks than gaps, there is no idle at all. Answer: max(len(tasks), (maxf - 1) * (n + 1) + count_max).

Speed & memory: one counting pass: O(T) time, O(k) memory. Fastest, but it only gives the length, never the schedule. The heap simulation (Solution 2) is the pattern; this formula is read off its picture.

When you'd use this

See "cooldown", "the same item at least n apart" or "no two equal neighbours"? Simulate with a max-heap of counts and park what just ran in a queue until it is allowed back.
